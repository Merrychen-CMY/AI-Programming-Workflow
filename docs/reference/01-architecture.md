# 1 统一回流架构

> 当前2.4用户流程补充：需求审核仅允许DOT编排；执行计划审核后才开工；成功或失败最终报告都须用户审核。成功报告获准再核对交付授权，失败确认不授权继续。以下正式技术阶段须同时满足此约束；本地运行器不实现外部交付。详见 [当前流程](../../DOT.md)。

> v2.0使用范围：本章保留原完整技术参考。默认用户流程为L1整理需求、用户批准、DOT执行；本章内部角色和正式工具契约按 [进阶范围](../advanced-profile.md) 适用，不要求用户逐层操作。

架构图的可检索 Mermaid 版本见 [架构与基线](../architecture.md)。

图 1  双 L1 基线与 L2 统一回流调度

流程控制器贯穿各层，保存状态、唯一标识、版本绑定、审批、权限、预算与证据引用。L2 负责根因分析和调度决策，控制器负责校验并执行；控制器本身不替代 L1、L1-V 或人工审批。Dot 可以承载 L2 的项目管理角色。L5 可以使用同一工作台汇报，但其验收汇总职责与 L2 调度职责必须分别记录。

正向流程为 Product L1 → 门1 → L2 拆解与协调 → L3 实现 → 门2 冻结候选 → L1-V 候选验证任务包 → V0 → L4 独立验证 → 门3 → L5 验收汇总和交付申请 → 门4 → delivery_guard。L1-V 的通用验收计划在开工前建立，候选冻结后再实例化。L4/L5 可立即停止不安全操作和保存证据，但所有恢复、修复或重试调度均须经过 L2；聊天回复不能替代控制器记录。
