# 2 四道门与职责边界

> 3.0适用范围：L1是唯一用户入口，在原始委托内代理批准需求、计划和变更，用户只审核L1最终报告。原技术契约保留，正式保护仍适用。见 [当前规则](../../AGENTS.md)；历史人工Ready/签名服务示例不自动授予L1身份或权限。

| 门禁 | 通过条件 | 决定者 | 未通过后的处理 |
| --- | --- | --- | --- |
| 门1 开工 | 产品需求、AC、代码起点、预设验收计划及预算已绑定 | 原始委托内的L1及独立审查 | 保持 READY；L2 汇总原因；需求决策提交 L1 |
| 门2 候选准入 | 写入者停止；范围合法；代码与产物来源完整 | 控制器和冻结程序 | L2 接收诊断并派发 L3 或受控构建维护者 |
| V0 验证准入 | 有效 L1-V 实例绑定本候选、计划、环境与预算 | 控制器校验有效授权 | 不启动 L4；L2 分诊，计划问题提交 L1-V |
| 门3 证据准入 | 必需验证完整、来源可信、版本匹配、无未处置失败 | govrail 调用证据验证器 | 停止放行；L4 或门禁产生问题单，统一交 L2 |
| 门4 交付 | 固定候选、证据、verdict、动作和目标获批准 | 授权审批人 | L5 记录待审或退回；有问题则交 L2 分诊 |

V0 是四道正式门禁之外的验证任务准入检查。门1授权实现范围；L1-V 定义如何验证以及满足何种条件可以提出交付申请；门4授权确切的交付动作。L1-V 与 L5 均不能自行授予合并、发布或生产刷写权限。L1-V 的候选实例授权规则详见第17节。

授权范围内的实现修复，由 L2 分诊后派发 L3，不重复申请门1；但必须生成新候选并重新验证。需求或 AC、操作授权范围发生变化时，由对应负责人决策并使受影响的批准失效。纯资源追加由L1批准并留痕，不因此撤销产品基线批准。门2、V0、门3及交付守卫不能被 L2 人工标绿。

## 2.1 各层职责与禁止事项

| 层级 | 职责与交付物 | 禁止事项 |
| --- | --- | --- |
| Product L1 | 决定产品需求、范围、约束与验收目标；发布产品基线、稳定 AC 和变更决定。 | 不以修改 AC 掩盖实现失败；不接管日常修复派单；AI不得冒充用户批准最终报告；L1可在原始委托内代理批准需求和计划。 |
| L1-V | 维护验证需求、验收计划与用例基线；定义 AC 映射、预期、覆盖、环境要求、证据和候选验证包。 | 不改变产品 AC；不以降低阈值或删除用例消除失败；不直接修改产品代码或授权交付。 |
| L2 | 统一接收问题、分析根因、分类、拆解任务、协调方案、管理依赖、分配处理者；维护问题单和影响分析。 | 不擅自改需求或测试基线；不替 L3 修代码、替 L4 写 PASS；不代替授权审批人批准交付。 |
| L3 | 按 L2 任务实现和修复产品代码；保留自测、提交、变更说明与根因对应关系。 | 不接受 L4/L5 绕过 L2 的正式修复派单；不改正式验收标准、覆盖历史或自证验收通过。 |
| L4 | 独立验证、测试环境与设施维护、身份确认、证据采集；提交可复现问题和重验结果。 | 不直接派 L3 修复；不自行变更测试预期、产品目标或批准例外；不把自测或缺失证据记为 PASS。 |
| L5 | 汇总逐项验收结论、失败历史和风险；评估交付可行性，准备申请、目标与回退方案并核对回执。 | 不绕过 L2 下达修复任务；不批准自己的交付申请、不豁免必需检查、不把门3 PASS 当作交付授权。 |

层级是责任边界，不要求一层必须对应一个产品或一个 AI。正式身份、访问权限和审计记录仍须隔离。默认中间批准由L1承担，独立审查与起草分离；用户最终报告批准独立于L1/L1-V/L5。正式服务需要真实代理身份映射。

## 2.2 工具与运行身份边界

| 角色 | 可以做 | 不能持有或修改 |
| --- | --- | --- |
| 需求 AI | 分析、提问、提出需求修改建议 | 你的审批凭证 |
| Dot 的 L2 角色 | 任务拆解、根因分析、依赖管理和回流调度 | 需求批准、正式证据、放行规则 |
| Codex / CAO | 修改授权代码、自测、提交候选 | 审批密钥、正式证据写权限、主分支绕过权限 |
| 验证程序 | 在隔离环境执行指定测试、上传结果 | 合并与生产发布权限 |
| 证据收集器 | 校验运行身份、保存日志和索引、生成可信回执 | 修改产品代码 |
| govrail 执行环境 | 读取固定策略和证据，生成结论 | 自行修改策略后重新认可自己 |
| 交付程序 | 对已批准对象执行一次指定动作 | 超范围发布和更换产物 |

Git worktree 只能分离工作目录，不能隔离凭证和宿主机权限。正式运行时，执行者与验证者至少使用不同系统身份或隔离运行环境；候选代码所在进程不能接触签名密钥。
