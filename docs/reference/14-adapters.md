# 14 需要实现的接入适配器

> v2.0使用范围：本章保留原完整技术参考。默认用户流程为L1整理需求、用户批准、DOT执行；本章内部角色和正式工具契约按 [进阶范围](../advanced-profile.md) 适用，不要求用户逐层操作。

这套流程不是安装几个插件后自动互通。建议按以下接口完成接入；所有接口都必须有结构校验、版本字段与明确错误码。

| 适配器 | 输入 | 输出 | 必须拒绝 |
| --- | --- | --- | --- |
| Ready 导出 | 正式需求版本与 Ready 记录 | launch 包 | 草稿、版本冲突、失效确认 |
| 审批服务 | 固定包哈希与认证动作 | 可校验审批回执 | AI 冒认、撤销或不匹配审批 |
| Dot 执行桥接 | task 契约 | 稳定 run_id 与任务状态 | 无门1、重复活动任务、越权路径 |
| 候选冻结与构建 | 精确代码版本 | 清单与不可变产物 | 脏工作区、写入未停止、构建来源不明 |
| 软件验证 wrapper | 候选与验收计划 | 原始报告及观察结果 | 零测试、缺报告、未批准跳过 |
| HIL wrapper | 固件与硬件计划 | 烧录及测试证据 | 固件不匹配、治具不符、身份未知 |
| 证据收集器 | 认证运行及文件 | 权威 JSONL 和封存证据集合 | 未知生产者、篡改、冲突事件 |
| 证据验证器 | 策略、候选、证据集合 | 固定门禁结论 | 缺检查、旧证据、未处置失败 |
| 交付守卫 | 门4批准与实际目标 | 交付回执 | 目标漂移、动作不匹配、重复消费 |
| 回流接收与分诊 | L4/L5 报告、门禁拒绝、原始证据 | issue、根因分类、影响和调度决定 | 无 L2 决定直接派修、未知根因自动改阈值 |
| L1-V 导出与 V0 | 产品/计划基线、冻结候选、授权 | 候选验证包与准入回执 | 无批准、候选/计划哈希不一致、超预算 |
| 重验与问题关闭 | L2 处理决定、新候选/计划、独立结果 | 新证据、verdict、问题关闭记录 | L3 自报完成即关闭、旧候选 PASS 复用 |

验收脚本、控制器、证据服务和上述适配器是本项目需要开发或接入已有系统的部分。教程中的 JSON/YAML 是它们的接口模板，不能声称这些接口已经由 Dot、CAO、govrail 或账本插件原生实现。
