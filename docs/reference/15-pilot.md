# 15 最小闭环演练

> 3.0适用范围：L1是唯一用户入口，在原始委托内代理批准需求、计划和变更，用户只审核L1最终报告。原技术契约保留，正式保护仍适用。见 [当前规则](../../AGENTS.md)；历史人工Ready/签名服务示例不自动授予L1身份或权限。

先用一个软件检查和一个 ESP32 串口应答任务跑通主线与回流支线。完整操作清单见21.1；本节保留最小操作顺序与原有拒绝测试。没有硬件条件时保持 HIL 为 BLOCKED，不能将软件通过解释为硬件验收通过。

1. 固定仓库、分支、板卡和工具版本，建立执行、验证、审批与交付权限隔离。

2. Product L1 确认需求/AC，L1-V 建立预设验收计划；生成开工包并完成门1。

3. L2 拆成一个任务、协调方案与依赖；通过控制器派发 L3，记录 run_id。

4. L3 实现、自测；L2 协调停止写入、集成、受控构建与候选冻结，通过门2。

5. L1-V 生成并授权候选验证包，经 V0 后由 L2 调度 L4 运行软件与 HIL 验收。

6. L4 保存证据；任何失败先报 L2，按根因调度并独立重验。收集器封存证据，govrail 检查门3。

7. L5 汇总 AC、风险和问题处置，申请对确切候选、证据、动作与目标的门4审批。

8. 交付守卫校验并执行，L5 核对实际落地回执；再演练一次 L4 → L2 → L3 → 新候选 → L4 的缺陷闭环。

在演练仓库与测试环境执行下列原有拒绝测试，并执行21.2新增的回流与版本拒绝测试。每项都保存预期、实际结果、触发入口、责任层和原始证据；全部通过才可启用相应自动化权限。

| 故意制造的情况 | 必须观察到的结果 |
| --- | --- |
| 没有门1就派单 | 控制器拒绝创建执行任务 |
| 替换 Ready Spec 内容但保留旧批准 | 哈希校验失败 |
| 使用旧候选的成功日志 | 门3因候选不匹配拒绝 |
| 只写一条 status=verified | 缺可信运行回执，拒绝 |
| 删除 HIL 结果或把它标为跳过 | 必需检查不完整，拒绝 |
| 测试执行数为零且退出码为 0 | 不放行 |
| 固件只打印 PASS，实际 PING 不响应 | 外部断言失败 |
| 篡改日志或生产者身份 | 哈希或身份校验失败 |
| 修改门禁脚本使其总是返回 0 | 可信控制版本或检查发布者校验拒绝 |
| 绕过本地 pre-push | 工作分支可上传，但主分支依然禁止合并 |
| 门4后目标分支发生变化 | 交付守卫拒绝 |
| 重放已经使用的审批 | 不重复执行交付 |
| 设备无空闲或网络失联 | ERROR 或 UNKNOWN，不生成 PASS |
| 流程中途重启后再次派单 | 返回既有运行，不创建第二个写入者 |
| 同一候选先功能失败后偶然成功 | 保留失败且拒绝自动洗成全绿 |
| 审批被撤销或已过期 | 新派发或交付被拒绝 |
