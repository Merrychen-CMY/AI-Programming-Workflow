# 19 安全隔离、证据可信与供应链防护

> v2.0使用范围：本章保留原完整技术参考。默认用户流程为L1整理需求、用户批准、DOT执行；本章内部角色和正式工具契约按 [进阶范围](../advanced-profile.md) 适用，不要求用户逐层操作。

## 19.1 执行环境隔离

- 候选代码、构建脚本和测试脚本视为不可信输入；在临时、最小权限环境运行。

- 执行候选代码的进程不得读取审批密钥、签名私钥、生产发布凭证或权威证据存储凭证。

- 限制构建/测试环境网络访问；确需下载依赖时使用受控代理、锁文件和来源校验。

- 限制 CI Token 权限、第三方 Action 来源和版本；保护工作流文件、控制仓库、验收用例与策略。

- Git worktree 不是安全隔离边界；应使用独立系统身份、容器/虚拟机或隔离 Runner。

- 对提示词注入、恶意依赖、构建脚本命令执行和 PR 工作流篡改进行拒绝测试。

## 19.2 证据真实性

SHA-256 只能证明被计算内容的完整性，不能单独证明测试真实发生或日志来源可信。正式证据必须同时具备受信运行身份、原始文件哈希、运行上下文、候选清单绑定和收集器回执。可采用受信 CI 身份证明、数字签名或具备独立访问控制与审计的不可覆盖对象存储；签名私钥不得暴露给候选代码执行进程。

- producer_id 必须由认证会话/受信 Runner 推导，不接受上传者自行声明。

- 原始日志先保存并计算哈希，再生成事件；缺日志、缺设备身份或采集失败时不得生成 PASS。

- 证据集合封存后不可覆盖；更正应追加新事件并保留旧记录。

- 验证器必须从受保护 control_commit 读取策略和必需检查清单，不能执行候选分支提供的门禁脚本来认可候选自身。

- 证据集合应包含所有尝试及失败记录，禁止只保留最后一次成功结果。

## 19.3 软件与硬件测试分层

| 层级 | 适合验证的内容 | 不应作出的过度声明 |
| --- | --- | --- |
| 云端标准板卡/通用 HIL | 启动、基础串口协议、基础烧录、简单外设和可远程观测项目 | 不能证明未接入的传感器、电气特性、射频环境或整机行为 |
| 本地真实硬件/专用治具 | GPIO/ADC/I2C/SPI、电源、传感器、电机、无线干扰、多板交互和整机联调 | 不能仅凭单台样机证明所有批次一致性 |
| 量产/现场验证 | 硬件版本差异、批次抽测、OTA、现场稳定性和回滚能力 | 不能假设所有 ESP32 分区方案都天然支持安全回滚 |

云端测试平台不能覆盖的 AC，应明确标记为需要本地治具或量产验证，并在 L1-V 中列出责任人、设备、证据和完成条件。不得把“设备不支持”自动等同于测试通过。
