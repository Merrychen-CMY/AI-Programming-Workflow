# 3.1.1 引导顺序验证范围

日期：2026-11-18。固定主线为：配置模型和密钥 → 检查环境 → 沟通原始需求 → 集中确认开工 → L1 自动推进 → 用户审核最终报告。

## 变更与验证

- 新增独立的 `workflow_check_environment`，配置模型/密钥并完成显式API兼容性测试后，先检查Python、Git、Codex CLI及登录。检查无需项目目录、需求草案或委托，不发送API请求、不派工，不向检查子进程传入API密钥。
- 基础环境通过后才主动沟通需求；需求明确后，`workflow_inspect` 补充复核项目特有条件并固定基线。原生开工确认、中间L1独立审查和代理批准、最终人工审核保持原有职责。
- 新增拒绝测试覆盖：未配置就检查、未检查就准备需求、基础检查失败、重查异常不能沿用旧PASS、已确认任务不能重置。原有配置变更、原生确认取消/跳过、UNKNOWN不重放及最终报告保真测试继续执行。
- 提示词、配置页提示、入口说明、流程图、状态约束、首次跑通步骤及模板同步为同一顺序；静态校验固定六个阶段及基础环境前置规则。

本机静态校验通过。Python完整回归共356项：353通过、3项因本机条件不支持而跳过，跳过不记为通过；Node插件测试21项全部通过。安装包使用校验后的MANIFEST构建；CI结果以对应提交的运行日志为准。
