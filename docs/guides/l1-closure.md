# L2 先分析，L1 决定非成功结案

所有问题先保留事实、证据和实际操作状态。L2 必须先考虑现有授权内的解决方案：说明方案、收益、验证步骤、风险、资源和权限缺口。已有授权和批准基线内的实现修复派 L3，设施恢复派 L4；不得直接修改产品、降低验收要求或越权重试。需要新权限、基线或资源时，将方案交 L1 评估，而不是宣告未知并结束。

L2 可暂停、提出问题或建议终止。控制器收到自动非成功报告请求时，将其转为 DECISION_PENDING；开工前转为 PLAN_REJECTED/L1_ASSESSMENT_REQUIRED。原始建议留档，没有 final-report.json。这个状态保留任务，L1 阅读证据，协调 L2 调查、修订方案或申请原生授权；恢复执行仍须原有门禁。只读调查不能清除真实未决操作，暂停不等于允许重放。

## L1 明确评估

只有 L1 显式调用 l1_stop 并提交完整评估，才产生非成功最终报告。保持 ABI6 的 reason 字符串参数，将 [评估模板](../../templates/l1-closure.example.json) 序列化为 JSON 传入；无需新增宿主工具。裸理由、空方案、空证据或不支持的终止依据返回 COMPLETED_REJECTED，不修改任务。

评估必须包含 summary、solutions_considered、authority_review、resource_review、termination_basis、evidence。依据只允许：no_feasible_solution（评估后无可行方案）、user_requested_stop（有实际用户结束请求）、unadjustable_total_limit（全任务限制已确认无法调整）。缺资料、缺权限、当前额度不足或原因尚未查明本身均不成立。用户要求立即停止时不应继续调查或额外派工，方案项应说明为何停止并引用原始请求。

控制器保存评估及当前状态摘要，报告中包含 l1_closure_assessment；之后仍须 L1 提交最终报告并由用户审核。结构校验不证明自然语言评估正确、不构成用户批准，也不是签名服务。L1 仍需核验引用原件，不能编造授权或终止理由。

## 覆盖入口

DOT 规划/执行 stop、独立审核结果未决、已有活动操作、运行守卫/文件异常、初始化基线冲突，以及旧模式实现/同根因/设施/审核/修订额度耗尽，都不能自动最终失败。常规 API 评估和动态预算评估仍使用原恢复入口。异常仅暂停；无法完成 L2 分析时记录待调查，不声称已分析。

历史已结案任务不自动撤销，真实 UNKNOWN 不清除。已开工任务仍固定旧运行版本；新规则须在采用新版后生效，迁移遵循原生确认和支持版本限制。
