# 同等能力、职责分工与 L1 资源管理

设计要求L1/L2/L3/L4/L5共享网页检索与抓取、文件读取与编辑、命令执行、环境查询和证据采集能力。实际接线分阶段完成：3.14.0的L2通过Codex委派调查，3.15.0扩展L1原生工具，3.16.0才为L2接通直接工具。职责限制行为，不再通过移除工具或按角色固定断网来表达职责。工具可见不代表某次任务授权了所有动作。

L1使用Harness原生web、fs、搜索、PowerShell/Bash与后台任务工具；后端沿用宿主现有配置。搜索提供方缺失凭据时如实报告，并用已授权的直接抓取或Codex调查，不能声称搜索已经通过。插件不替用户创建搜索服务账户。

所有独立Codex角色使用同一workspace-write配置，启用网络和在线搜索；工作目录、任务范围和审批记录仍保持隔离。实现者按派工修改；测试者独立验证；审核者和调查者可以查网页、读文件、查询工具路径与版本，不能借此修改产品或顺手跑测试。L5由DOT承担，具有同一调查入口，仍负责汇总与交付风险，不自批发布。

开工前L1可用原生工具澄清环境与资料，不开始产品实现。确认开工后，即使尚未批准需求或初始化，L1也可调用dot_research(question)。DOT在规划、根因分析与执行决策中可调用request_investigation，通过同一Codex能力收集资料并将结果直接送回DOT。无需先形成完整执行计划才允许调查。

调查保存问题、来源、命令结果、原始证据和摘要，计入总时间，不计为实现派工或需求修订。调查不改变需求批准；它只能补技术依据，不能覆盖目标、硬约束、验收或操作权限。方案采用的技术依据必须进入执行计划及独立审核；改变需求时仍走L1修订。不得伪造已确认事实或把参考值当实测。

系统环境问题同样先由DOT自行调查或安排调查者处理：检查SDK/工具链安装位置与版本、PATH、Python环境、依赖清单、串口可见性和已有构建日志，提交实际观察和最小修复方案，不要求用户代做可自动查询的工作。环境查询不等于运行产品测试；需要构建复现、安装依赖或设备操作时，按既有授权安排L3/L4执行，缺少权限则由L1协调。资源追加由L1批准；确实需要用户登录、提供凭据或连接实体设备时才说明具体人工动作。

资源额度、次数、API输出上限、单次等待和总运行时长由L1制定并自主批准追加。达到额度先交L1评估，记录剩余工作、证据、收益、策略、调整前后数值和累计消耗；纯资源追加不需要用户审批，不触发需求重审，不重置账本。L1仍须选择具体有限数值，不能无限循环。

用户明确的目标、硬约束、验收标准、文件/设备/网络/交付范围和最终截止时间不是普通资源参数；变更仍需用户确认。总运行时长可以由L1调整，但不得悄悄越过用户指定日期。平台账户余额、供应商硬限额和模型上下文规格不是插件可修改的额度；L1应更换可行方案或说明真实外部阻碍，不虚称额度已解锁。

新任务开工摘要自动包含L1资源管理委托。已开工任务不重写原确认；安装ABI10主包后，通过已有原生任务升级一次性采用新规则，升级界面明确显示资源管理变更，之后的资源追加无需用户审批。历史计数、未知操作保护及终态保留。旧任务仍固定旧运行版本时不会自动得到新能力。

最小验证场景：提出一个缺工具版本或官方资料的LED任务 → DOT发起调查 → 收到真实来源与路径 → 给出计划 → L1独立审核；把当前API/审查额度设低 → 暂停交L1 → L1批准增加 → 原任务继续且历史消耗不变。自动化测试使用隔离夹具，不代表真实LED或HIL验收。

L2协助完善需求：发现L1需求不完整，先主动查资料、查环境和相关代码，必要时安排调查智能体；提交已核实事实及来源、具体需求修订建议、理由、验收/验证影响和剩余决策。L1据此完善需求并组织独立审核，L2不得只退回问题，也不得把建议冒充已批准基线。普通技术查证直接供规划使用，不必重复要求用户提供。

## 3.15.0：L1 原生工具完整配置

ReqPilot预设显式启用文件读取、图片读取、写入、编辑、多文件补丁、目录/内容搜索、PowerShell或Bash、后台任务、网页检索和抓取。目录的创建、列举、移动和删除使用命令工具或补丁完成；命令工具不设置“仅版本查询”的白名单，按当前任务和已有授权使用。

同时启用技能发现与调用、子智能体创建/分支/通信/等待/中断、协作工作流、待办、目标、定时工具、文档处理、文件展示及Harness运行时/插件管理工具。继承宿主已经挂载的工作目录、终端、团队及其他公共服务；不重复安装同名服务。模型路由、附件、搜索服务凭据和宿主组件决定工具能否实际执行，插件不声称创造宿主未提供的能力。

L1可直接查文件、探测版本、定位依赖与SDK、抓取资料，并安排辅助智能体调查。职责决定何时使用工具：原生辅助会话交回事实和建议；受控产品实现、独立测试/审核及批准仍走DOT和ReqPilot记录，不能用普通子会话冒充已登记的独立验收。工具存在不代表已经执行成功。

本版安装包为ABI10。必须安装/重新加载主插件；运行文件更新不替换已创建Agent的工具组合。Harness官方预设机制只保证新创建的Agent取得新定义，不能声称已运行的旧Agent会即时获得工具。保留原对话和任务目录，通过宿主重新加载/恢复后核对实际工具；必要时使用新Agent，但不得新建任务冒充旧任务恢复。已开工任务仍通过原生版本升级保留授权和消耗。

能力验收：在授权临时目录创建子目录和文本，读取、修改并核对；查询Python/CMake等实际路径与版本；抓取一页已授权官方资料；查看技能、后台任务和子智能体工具是否存在。记录真实结果，不将工具清单当作调用成功。宿主权限拒绝、提供方未配置和模型不支持图片等分别报告，不笼统声称“L1没有能力”。


## 3.16.0：L2/DOT 直接工具

| 工具 | 实际行为 |
| --- | --- |
| local_read / local_list | 分页读取UTF-8文本、列举目录，读取文件返回摘要哈希；可读取项目外SDK/工具资料。 |
| local_write / local_edit / local_mkdir | 创建、写入、精确替换和创建目录；已有文件须匹配读取时的哈希，避免覆盖已变化内容。 |
| local_command | 直接执行参数列表，可显式调用PowerShell/Bash做搜索、环境诊断和其他已授权操作；记录退出码、原始输出与进程信息。 |
| web_fetch | 直接获取HTTP(S)资料，保存原始字节和摘要；重定向先返回目标供核对，二进制可交本机工具解析。 |
| web_search | 用当前配置的GPT模型调用Responses内置搜索，保留搜索完成状态、链接和引用；追加一次真实API账本记录。 |
| request_investigation | 仍可选择独立Codex调查；不再是L2访问文件、命令和网页的唯一办法。 |

工具出现在规划、执行决策和L2根因分析请求中。不是给GPT一份工具清单：运行器实际执行调用，并以匹配的call_id返回function_call_output；无状态请求保留全部输出项和加密reasoning项。历史及工具定义一起接受材料大小检查，不静默裁掉来源或失败。协议依据：[OpenAI函数调用](https://developers.openai.com/api/docs/guides/function-calling)、[网页搜索](https://developers.openai.com/api/docs/guides/tools-web-search)。

L2工作材料放在control/l2-workspace；文件写入工具同时检查当前委托允许的产品路径，拒绝越界、控制记录和元数据写入。工具没有“仅版本查询”的命令白名单；调用者必须遵守当前职责，规划/诊断不开始产品实现或擅跑测试。直接命令使用本机当前用户权限，工作目录与文件工具的路径检查不构成命令沙箱。同账户进程仍能越过普通文件约束，因此不能宣称强隔离。不给GPT暴露L1批准工具，不把一次命令退出0视为独立验收。

每次直接工具调用写入research/<id>/record.json，原始下载、命令日志和进程记录一起留存，纳入既有状态查询、审核来源与恢复记录。普通错误作为具体失败结果交回DOT继续分析，不生成最终失败；资源/API异常仍由L1评估；进程结果未核实则暂停后续执行，保留原记录并走既有恢复入口。调查不占实现派工或需求修订次数，所有API请求和时间累计不清零。命令不接收OPENAI_API_KEY环境变量，禁止在参数、下载URL或返回给模型的材料中放凭据。

单次文字/目录返回分页上限16000字符/项，命令返回前16000字节且完整日志仍在；网页便捷抓取最多8MiB，较大资料用已授权下载命令保存再分页分析。以上是工具传输边界，不删除完整命令证据，也不将超限判为产品失败。未安装的PDF/图像解析器、账号不支持的搜索模型和宿主专属服务不会凭空可用；返回具体缺口，L2选择已授权替代方法或交L1协调。

本版保留ABI10，不新增L1工具名称或宿主服务依赖。已有3.15.0主插件可检查兼容更新；已开工任务须执行原生任务升级并核对workflow_runtime.version为3.16.0，原授权和累计消耗保留。仍固定旧运行版本的任务不会自动得到L2直接工具。此次不需要为L2另填密钥或另建用户对话。
