# 回流问题操作

## 发现层 L4 或 L5

保存原始结果与对象绑定，填写 [问题模板](../../templates/issue-intake.json)，将其提交给L2。记录预期、实际、复现方法、证据及影响；根因可以提出假设，但不能直接指定代码修复任务。

## L2 分诊

依据 [结构化策略](../../policy/workflow.json) 和对应矩阵确认分类。将根因依据、处理层、允许路径、预算、受影响依赖及重验范围写入调度记录。未知根因先组织诊断，不把FAIL自动等同于实现缺陷。

任务/技术方案问题由L2协调；产品语义交L1；测试语义交L1-V；实现修复派L3；设施恢复派L4；交付目标与授权由L5整理申请。混合根因拆关联子单。

## 完成与关闭

处理者提交变更和证据，L2校验影响；需要新候选/计划时先更新对象和批准。L4独立重验后由受信验证器重新判定门3，L2再关单。纯审批事项按审批服务与交付守卫核验，L5复核。失败重回分诊，原记录保留。

同因失败、预算、未知运行或权限问题按 [升级规则](../../policy/escalation.json) 处置。自动恢复只能依据明确预授权和持久化计数；不能靠聊天里的“再试一次”绕过限制。
