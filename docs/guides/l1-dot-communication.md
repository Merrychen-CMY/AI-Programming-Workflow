# L1与DOT的合作沟通约束

采用格赖斯合作原则作为沟通约束：信息充分且不过量（量）、陈述有据（质）、内容相关（关系）、表达清楚有序（方式）。来源为Grice的[《Logic and Conversation》1975年，第45～47页](https://www.sfu.ca/~jeffpell/Cogs300/GriceLogicConvers75.pdf)。下述消息规则是本项目的工程化采用，不是原文提出的Agent协议。

预期作用是减少重复背景、无效确认、版本误解与不明确请求。**这是合理的设计判断，尚未在本项目实际L1→GPT/DOT任务中测得效率提升。** 不以更短、更快为由降低准确性、授权和证据要求，也不要求双方无条件赞同。

权威机器规则：[policy/communication.json](../../policy/communication.json)，revision 4。COMM-01～04适用于所有项目的L1与DOT往来；支撑这些交流的工作会话报告同样应提供清楚的结论与证据。C编码内容仍按华为及Doxygen要求，不改变现有规范优先级。

## 四项准则如何执行

| 准则 | 本项目执行要求 | 不允许的简化 |
| --- | --- | --- |
| COMM-01 量 | 先结论或请求，再给足以执行的信息；已共享、可核实的内容引用固定基线，后续说明变化和影响 | 只写“同上”；省略失败/风险；无状态API只收到一个无法读取的本地路径 |
| COMM-02 质 | 已观察事实、推断、假设与未知分清；状态绑定候选、真实回执和证据 | 将建议写成批准；把未执行写成PASS；把无异常当成功；把推测根因写成定论 |
| COMM-03 关系 | 围绕当前需求、任务、问题或决定；关联风险及时说明，按正确责任回流 | 用“只说重点”隐去阻断或剩余风险；将讨论扩展为任务外修改 |
| COMM-04 方式 | 先结论，再依据，再下一步；明确对象、版本、单位、条件和责任人 | “最新版”“差不多好了”等无法核对的表述；只有长篇过程却没有结果或请求 |

合作不等于服从或附和。独立审核发现错误必须明确反对，并给出依据；不能为保持一致而修改验收目标或隐藏冲突。也不采用会话含意推断授权：沉默、收到、没有反对、语气肯定都不是批准。

## 轻量消息结构

优先使用现有需求、计划、状态和结果字段，无需新增表格或新的传输协议。自然语言说明使用两项基本信息，其他项按实际需要补充：

1. **目的和对象**：本次请求、方案建议、决定、结果或阻断；指出相关需求/任务/问题及已有版本。
2. **结论或请求**：已经发生什么，或需要接收方做什么。
3. **变化和影响（适用时）**：相对哪个已共享基线改变了什么，影响哪些AC、检查、候选、权限或预算。
4. **依据和可信范围（适用时）**：实际观察、证据引用/关键内容、推断和未知；不得省略支持结论所必需的内容。
5. **待决项（适用时）**：必要缺口、推荐处理及影响，合理备选仅在能帮助决策时给出。
6. **下一步（适用时）**：责任人、动作及恢复条件；已有明确下一步时不重复索要确认。

可用REQUEST、PROPOSAL、DECISION、RESULT、BLOCKED作目的标签。它们**不是新的工作流状态或工具参数**，也不产生权限；DECISION必须指向真实既有审批记录，不能自行写“已批准”替代审批工具。参考[简短模板](../../templates/l1-dot-message.md)。

工具调用仍严格满足原JSON结构，说明放入已有requirements、description、summary、reason、instruction等适用字符串中；不要添加工具不支持的键。完整需求、计划、结构化回执和证据仍按现有门禁保留，不能为了套用消息模板而缩成缺字段的摘要。没有固定字数上限，也不要求每句话加事实标签。

## 交接、回流和上下文

| 场景 | 至少让接收方知道 |
| --- | --- |
| L1首次交DOT规划 | 目标、AC、硬约束、环境、允许范围、权限和预算；未确认事实明确列出 |
| DOT提交计划 | 方案、任务/依赖、验证安排、风险和待决项；说明这是待L1审核的提案 |
| L1批准/退回 | 具体对象与版本、批准工具回执或明确退回原因；批准范围不能靠语气推测 |
| DOT问题回流 | 观察事实与证据、根因判断及可信范围、已尝试动作/累计消耗、建议责任人和恢复条件 |
| L1修订后交回 | 原/新版本及变更、影响与重新批准记录；不得复用失效批准或旧候选PASS |
| DOT最终结果交L1 | AC结果、最终候选、独立证据、全部失败历史、消耗、未验证项、产物和风险 |

增量说明以接收方**确实可取得、核对了同一基线**为前提。API没有文件读取工具时，本地文件路径、GitHub链接或哈希本身不提供内容；应带上本次判断所需文本/数据和证据关键内容。新会话或无状态请求补齐必要上下文，不假设对方记住上一次。

GPT调用仍是独立请求，当前需求、计划、权限和必要环境保持可核验。3.21.0由本地代码对历史观察生成有界视图，保留原件引用，不调用另一个模型摘要，也不假设服务端记忆。完整请求目标230000字节，历史观察目标40000字节；这是可读视图目标，不能删掉批准基线、调用配对或推理协议项目来凑数。超过最终250000字节上限仍在发送前明确拒绝。

遇到缺口先查已有资料，将相互关联的关键问题集中列清，说明影响和建议。缺关键事实时不猜测、不执行依赖动作；无关且已授权的工作可继续。委托内由L1/DOT按原回流处理，L2先提出权限内方案，越界交L1评估并按需申请原生授权；只有L1明确评估后才能非成功结案。

接收方直接给结果、必要异议或具体缺口，不强制增加“收到→确认收到”一轮。确有版本不符、歧义、权限不足或失败必须反馈。无新事实不重复同一请求；沟通遵守原尝试、API和时间上限，UNKNOWN先核实旧过程，不能借“重新问一次”重放执行。

## 消息示例

以下为虚构的待决说明，不是产品证据或批准。模板名称仅用于演示。

> **目的/对象：** PROPOSAL，任务T-07，候选C-12，问题ISS-04。
>
> **结论/请求：** 请求L1内部L1-V核查超时用例预期；不建议直接派代码修复。
>
> **事实：** 需求R3规定阈值为100 ms，测试计划V2写成80 ms，当前观测为90 ms。证据条目E-07附这三个原始字段，接收方可核对。
>
> **推断/未知：** 可能是测试计划未同步；尚未确认测试时钟与测量误差，因此不能判产品通过。
>
> **下一步：** L1-V核对基线；需修改计划则由L1独立审查并重新批准，DOT安排受影响检查重跑。保持原始AC和累计预算。

这段说明既给出可行动建议，也保留了可能改变结论的未知。不能改成“已经修复、继续即可”，也无需在每次回复重新粘贴整个项目背景。

## 接线与验证边界

- L1工具桥初始化提供本规则；GPT每次规划、调度和分诊请求的开发者指令中包含简短执行要求；L1独立审批审查提示同步包含。
- 不增加工具、API往返、审批环节或用户表格；模型仍使用既有工具参数和结果结构。输入上限检查计入新增指令，超限明确失败而非截断。
- 沟通策略摘要纳入批准及候选基线；规则发生变化时旧批准不能静默沿用。升级应按现有基线变更流程处理。
- 仓库校验保护四项准则与授权/证据边界，测试验证提示传播、基线失效和现有流程兼容。**没有自动证明每条自然语言都真实、相关或充分**；模型实际行为仍需审查。
- 后续可用已有记录比较澄清轮数、重复上下文、形成可执行决定的耗时、版本/路由误解返工及必需证据遗漏。不能只看Token或耗时，也不因未测量新增阻断或用户报表。

## L1面向用户的表达

同一策略中的L1-EXPR-01～05有条件借鉴anti-defensive-writing，具体取舍见[L1用户沟通指南](l1-user-expression.md)。另按用户要求加入progress_report固定六字段进度格式，来源为本项目用户偏好，不归因于上游写作Skill。仅约束L1面向用户的自然语言；原始事实、授权、验收、证据和编码规范优先。MCP初始化及L1独立审查收到这部分规则，GPT/DOT仍使用COMM-01～04及既有执行规则；不把原论文Skill或其精简提示词整体载入。新增策略内容同样参与基线摘要，旧批准和候选不能静默复用。

## 3.21.0：精简智能体对话

共同顺序是：**结论/请求 → 本次变化 → 必要证据 → 下一步及责任人**。这只是现有字符串字段的写法，不新增工具参数、审批或字数硬限。

- 去掉重复的“我没有权限”“这不代表交付”“我不能保证”等泛化免责；当前状态已经明确时无需每段重述。
- 当前确有未获授权动作、未核实操作或未完成验收时，直接写具体缺口及处理人，不能把它当套话删除。
- 不重复整份需求、规则、完整历史或“收到→确认收到”。首次交接保留必要基线；后续写变化并引用可读取、哈希绑定的原件。
- 已有足够证据支持修复就提交最小方案；继续调查须说明具体未解问题及需要新增的证据。只是改写原结论不算进展。

例如：`ISSUE-0003：Doxygen发现event_index重复@param。证据E-07。建议L3仅删除重复条目，生成新候选；L4重跑文档检查和受影响验证。` 当前若缺设备授权，再加一句具体缺口即可，无须附整段通用免责声明。例子不授权实际产品修改。

规则由同一communication策略传给L1、DOT及独立执行会话；真实对话是否收敛仍需任务观察。不得宣称已测得美元节省比例。
