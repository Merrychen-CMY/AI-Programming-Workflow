# 不改变流程的提效与故障处理

L1→DOT/L2→L3/L4→L5→L1报告的顺序、职责、权限、审批和终态保护保持不变。以下为原步骤内部的处理优化。

## 材料与事实

- 规划材料中的环境说明使用16 KB有界视图；原件在api/materials下保留哈希绑定，DOT可用read_evidence读取缺失部分。
- 补充事实按planning/build/test/documentation/delivery分组，仅合并名称、值、来源、阶段均相同的事实。不同值或不同来源并列保留，不自动认定后来的说法正确。完整修订链保留；已批准需求、授权和验收不截断。
- 调查上下文优先最新记录，包含有界实际观察、时间、来源及新鲜度说明；旧失败不删除。新调查先看到已有资料，调查者只补缺口或复核变化。
- local_read复用仅限相同参数、解析路径、当前授权和重新读取计算的内容哈希一致的成功页面；新的调用留下记录和原证据引用。文件改变、删除、拒绝访问或权限改变不会返回旧内容。仍须读取文件以核验哈希，这不是免读文件缓存。
- 命令、网页、目录列表、设备状态、写操作和验收结果不自动复用。环境版本可作为历史观察引用，但投入后续执行前按实际依赖核实；不以缓存代替当前环境探测。
- 原生L1入口只去掉不同入口文件中完全相同、单行且不少于300字符的版本说明段落；第一处完整保留。其他角色文字、代码和不同措辞保留，不对规则进行语义删减。

## 收到故障后的步骤

工具结果和dot_status可返回recovery_advice，包括责任人、排查步骤、核验方法和既有入口。它只是可执行建议，不能批准动作或自动恢复状态。

| 故障 | 先做什么 | 怎样继续 |
| --- | --- | --- |
| 文件或工具路径不存在 | 查最近存在的父目录，限定范围定位；核对是否缺少前置产物 | 使用查证后的路径或提出前置动作，不创建假文件 |
| 文件访问被拒绝 | 核对锁、权限、加密环境与真实消费者 | 走既有文件诊断/恢复；不关闭安全软件 |
| 文本解码失败 | 核实格式与编码，选择已安装且获准的读取工具 | 原件不变，核对提取内容及缺失范围 |
| 材料超限 | 查看分项大小，使用去重事实和原件引用 | 已批准需求需要改写时，重新独立审核与L1批准 |
| 草案校验拒绝 | 读保存的草案及校验反馈，修正具体问题 | 沿用一次草案纠正与后续L1评估，不扩大预算或删验收 |
| 额度不足 | DOT提交剩余工作、消耗和方案 | L1通过现有入口评估批准，历史用量不变 |
| API失败 | 分清未发送、明确拒绝与结果未决 | L1评估；不以延长超时冒充旧请求已确认 |
| 审核问题或其他执行决策 | 阅读最新发现，L2补证据并提出方案 | 需求准备或初始化后的调查/恢复入口按当前状态选择 |
| 报告写入失败 | 保留已完成审核和原结论，查文件写入条件 | 使用原报告补生成入口，不重新执行审核 |

报告写入恢复继续沿用COMPLETED_REPORT_PENDING返回的现有说明；此版本没有新建报告恢复入口。

## 阶段、重复失败和继续执行

NEEDS_INFO按现有stage字段分组，帮助L2识别哪些是规划必需条件，哪些属于后续验证。后续条件不能任意豁免；只有现有计划能约束依赖时，才能继续不受影响工作。涉及需求修订仍由L1完善并独立审核。

同一API工具对话中，重复的调查问题第一次重复时返回原观察，不另派调查者；明确标记不是新测量。再次要求同样调查则进入现有NEEDS_INFO路径，要求具体替代方案。连续相同的失败工具调用第一次重复时返回NOT_EXECUTED及排查提示，第三次原样请求升级给L1协调。不同诊断动作仍可执行；未决操作保持既有禁止重放机制。这不是跨任务的通用故障判重器，也不保证识别所有换措辞的循环。

原有任务完成记录、修订后的依赖失效判定、候选冻结和完整重验继续使用。不能以提效跳过独立审核或复制旧PASS。

## 可重复验证

运行 `python scripts/benchmark_efficiency.py` 可在临时目录执行“错误路径→查找→重复读取复用→需求/计划审核→实现→独立验证→成功待审核”的固定场景，输出耗时、API请求数、实现次数、事实修订数、复用页面数和保留的失败数。模型与审批是模拟的，测试子进程真实执行；不会访问用户工程或付费API。耗时只适合相同环境比较，不代表实际项目提速比例。

回归覆盖大环境材料、冲突事实、文件/授权改变、重复失败、API未决、额度及终态保护；现有文件环境测试继续覆盖加密视图异常。真实模型选择解决方案、真实加密软件及硬件仍须实际项目验证。
