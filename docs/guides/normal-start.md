# 正常开工链路与审查材料交接

用户主线仍为：配置模型与密钥 → 检查环境 → 沟通需求 → 集中确认开工 → L1自动推进 → 用户审核最终报告。3.8.0修复内部交接，不新增普通中间用户审批。

## 执行顺序

1. 开工确认后，L1在用户授权内分配额度，DOT生成计划并初始化。
2. `REVIEW_PENDING`：L1调用`l1_approve(kind="requirements")`。只有通过后才进入`PLAN_PENDING`。
3. `PLAN_PENDING`：L1调用`l1_approve(kind="plan")`。通过后进入`EXECUTING`，才能`dot_run`。
4. 审查FAIL进入`DECISION_PENDING`。先查看`latest_review.findings`，修正受影响基线并用`l1_revise`提交，再重新审查。不得尝试批准计划跳过未通过的需求。
5. 额度不足先由L1评估；可在授权内调整当前额度，超过用户上限则提出具体追加授权并通过原生确认。无可行方案才提交最终报告，不将当前额度耗尽等同于产品失败。

错误的审批顺序或未批准就请求执行，返回`accepted=false`、`operation_status=COMPLETED_REJECTED`。它不发起新的审查或DOT请求，也不改变批准、消耗或原阶段。宿主只移除本次已正常结束调用的占位；旧中断、活动执行、真正UNKNOWN以及最终报告仍保持保护。

## 程序准备证据，L1不重复搬运

独立审查输入目录含`source-index.json`及`sources/`：

- 已确认的环境检查原始结果与确认绑定；存在性/人工声明不升级为实际构建或HIL通过。
- 控制器初始快照、带时间及运行ID的累计用量；计数包括本次预留的审查。
- 原始API账本、资源调整、API评估/后续请求授权及当前未决状态。
- 本运行版本的计划契约、DOT职责、嵌入式C/Huawei/Doxygen资料，按项目类型选读。

这些是控制器已有材料的快照，不是新的用户需求，也不消耗事实补充或基线修订次数。真实新增事实与需求/计划变更仍走原有修订与独立复核机制；3.8.0没有清零历史或放宽用户上限。

L1不应在需求正文反复抄写瞬时墙钟与累计计数作为永久事实。需要引用时注明时间点，审查以当前控制器快照核对；不同时间的计数变化不自动构成冲突。历史UNKNOWN即使已有后续请求授权也不得改成成功；用当前未决列表判断是否仍阻断。

审查包记录每个输入文件摘要，审查后检测材料变化；变化时不批准。批准后输入和审查输出都纳入证据完整性校验。本地摘要仍不是可信签名服务。

## 简短回执和完整记录

状态返回当前阶段、最新审查摘要/问题、当前用量和下一步，不反复嵌入全部命令输出和历史审查。过长细节会明确标为abridged，完整磁盘记录保留。

L1使用只读工具：

```json
{"path":"run/l1-reviews/2/result.json","offset":"0"}
```

工具名称为`dot_read_record`；按返回的`next_offset`继续，每页最多6000字符。路径从本任务`control/`起算，只能读取允许的状态、计划、审查材料及报告；拒绝越界、符号链接和任意凭据/API请求文件。它不启动API或工作会话，不清除中断，在旧中断存在时也允许读取已有记录（任务运行版本须支持此工具）。

最终报告确认展示摘要、完整文件位置及原始报告摘要校验值；用户可要求L1分页展示完整报告后确认。确认仍绑定完整报告，期间变化会被拒绝。

## 安装、验证与已有任务

新增只读工具需要ABI6宿主，须安装3.8.0插件包后加载新增入口。已确认任务仍固定原版本；新宿主能够读取旧版本状态，但不会让旧版本获得新工具。既有UNKNOWN或终态任务不得借更新自动重开。

回归覆盖真实插件JS调用、Python子进程管道、控制器和本地测试命令，包含一次错误顺序拒绝后继续审批直至最终报告。此测试的模型回答、环境探测和原生用户答案为模拟；不是实际Harness桌面会话或ESP32/HIL验收。真实使用仍需单独记录，不能仅凭测试数量宣称正常流程已在用户环境全面跑通。
