# Doxygen注释参考与实际检查

本项目采用[viys/doxygen_stu的固定版本](../../standards/embedded-c/v1.3/doxygen/source.json)，具体规则见[12项采用决定及33个子要求](../../standards/embedded-c/v1.3/doxygen/README.md)。**与华为规范冲突时，以华为规范为准**。Doxygen参考补充注释语法、实体示例和文档组织，不覆盖华为的命名、内容、排版和注释位置要求。

## 读取与编写

L3先读采用清单，再使用[头文件示例](../../standards/embedded-c/v1.3/doxygen/examples/commented_module.h)和[实现文件示例](../../standards/embedded-c/v1.3/doxygen/examples/commented_module.c)。示例覆盖文件、函数、结构体、枚举及成员、宏、全局/静态变量和内部函数，包含参数方向、返回说明、详细约束、风险、引用和成对代码块；教学元数据和示例值必须换为真实项目内容。静态变量使用`s_`；文件头不能因上游模板简短而省略华为要求的真实信息。`/**< ... */`仅用于目标同一行右侧，长说明放在目标上方。

统一使用[最小Doxyfile模板](../../standards/embedded-c/v1.3/doxygen/templates/Doxyfile)生成浏览用HTML/XML时，按真实工作目录和自有源码配置路径。它不是产品已经通过的证据。运行期门禁由受控脚本生成自己的配置，避免项目Doxyfile抑制警告或执行输入过滤命令；模板变更不自动改变门禁规则。

## 单独执行

参考验证版本为Doxygen **1.18.0**。安装位置由项目明确，工具缺失不会被当作跳过通过。以下命令需要替换成真实路径，输出目录必须是源码之外的新目录：

```text
python <工作流仓库>/scripts/check_doxygen.py --source-root <产品候选目录> --include src --include include --output-dir <独立证据目录> --doxygen <Doxygen可执行文件> --expected-version 1.18.0 --timeout 120
```

`--include`可重复指定自有文件或目录；省略时选取源码根内全部`.c/.h`，不会自动识别第三方或生成代码。DOT必须明确选择范围和排除依据。路径越界、链接、无C输入或复用非空输出目录会拒绝。此处的源码集合摘要只绑定被选文件；完整候选绑定由控制器额外核对。

脚本实际运行版本查询与Doxygen生成，保留原始输出、警告、受控配置和XML，并输出`report.json`。仅PASS返回0；工具缺失、版本不符、超时、非零退出、告警、缺失/无效XML、源码变化或可见实体/参数/返回说明缺失都不能通过。`UNKNOWN`表示无法确认旧进程已停止，必须先核对进程和副作用。

XML检查覆盖Doxygen可见的文件、类型、宏、枚举值、变量、静态函数和公共函数文档，以及函数参数名/方向和返回说明。文档实体数量不是业务测试数量，不能替代原有行为测试。配置关闭`EXTRACT_ALL`并提取静态实体，防止默认“全部已文档化”掩盖缺失；受控脚本收集全部诊断后统一返回失败，不能因Doxygen退出0就判通过。

默认门禁也要求简单内部函数具备基本结构文档，不要求无意义的长模板。函数式宏的参数、求值次数与副作用契约仍需独立审查；当前工具对宏检查文档存在，不能宣称已自动核对这些语义。

## DOT运行器接线

[本地执行计划](../../templates/local-execution-plan.example.json)中的`coding_standard: huawei-c`必须提供：

```json
"doxygen": {
  "executable": "REPLACE_WITH_APPROVED_DOXYGEN_EXECUTABLE",
  "expected_version": "1.18.0",
  "include": ["src", "include"],
  "timeout_seconds": 120
}
```

该对象位于`verification`内，由DOT在原执行计划中填写，用户沿用需求、计划、最终报告三次审核。源码范围必须涵盖适用自有代码，不能只挑有注释的文件通过。旧C计划缺少该对象时必须补齐并重审；规范和检查脚本的摘要也绑定计划批准，更新后不能沿用旧批准。

`executable`填写已审核的绝对路径，或可在PATH解析的工具名称；不使用依赖工作目录的相对工具路径。`expected_version`固定到实际安装的三段版本号，不能填写latest或任意匹配范围。

控制器在独立测试/审核会话前，对候选的独立副本直接执行已固定的文档检查脚本，不依赖Agent自填工具已运行。检查报告必须匹配选定候选文件、配置、精确版本、原始命令与XML摘要；审查会话读取具体DOX要求和当前候选的真实文档报告。检查失败统一交DOT/L2分析，区分注释实现缺陷、验证计划或工具设施问题后调度；不能直接由L4要求L3盲目重试。最终报告保留各次文档检查和原始证据。

## 独立审查与适用范围

工具不判断注释是否真实描述行为、作者/版权是否真实、参数单位/所有权/并发要求是否正确。L4仍需逐项核对DOX采用清单，并在既有DOC-001及HW-S-8.3审查证据中记录适用性、结论和具体依据；父项或工具PASS不能代替子要求审查。

Doxygen不是完整C编译器。条件编译未激活分支、平台扩展、生成接口、构建宏配置及工具不可见实体须另外审查，必要时按实际构建配置追加检查。Kconfig不在本脚本的C输入范围内；只有经审核的转换/过滤及实际生成证据才能声称已文档化。缺失这些证据时保留NOT_RUN/BLOCKED，不能借格式检查扩大产品验收结论。

## 维护者验证

`python scripts/verify_doxygen_examples.py --doxygen <真实可执行文件> --expected-version 1.18.0`实际调用Doxygen验证示例和破坏注释的拒绝场景。CI使用固定官方版本及下载SHA-256，和模拟故障的单元测试分开。上述示例验证不表示已经编译或验收用户产品。
