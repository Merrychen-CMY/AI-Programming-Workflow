# 候选测试契约与设施恢复

3.13.0把测试对象来源与必需测试结果纳入运行门禁。测试进程返回0、在候选目录启动、打印非零数量或模型声称通过，都不能单独证明当前候选通过验收。需求/AC由L1决定，内部L1-V维护验证义务；DOT把这些义务写成计划，独立审查及L1批准后才执行。

## 计划必须明确的内容

`verification.test_contract`声明受控协议、`required_tests`精确测试ID、`not_applicable_tests`中允许不适用的ID及理由、`source_root`和`product_files`。Python协议为`python-unittest`或`python-pytest`；CMake协议为`cmake-ctest`，另列`cmake.executable`、`configure_args`、`build_args`。具体有效形状以[计划模板](../../templates/local-execution-plan.example.json)和运行器校验为准。

必需项缺失、失败、跳过都不能成功。平台确实不适用的项须在获批计划中明确列出并说明依据，不允许失败后临时增加豁免。改变义务、测试语义或豁免须经内部L1-V评估、独立审核和L1重新批准；改变用户AC还须用户批准。

测试ID必须能与真实运行结果逐项对应。unittest使用完整`module.Class.method`，例如`test_value.Test.test_value`；pytest使用完整nodeid，例如`test_value.py::Test::test_value`，并保留参数化后缀；CTest使用测试名称。同名方法可通过模块和类区分，无须改写测试源码。DOT应在审核前确认准确ID，不能在执行失败后降低标准。任意包装脚本、自定义打印PASS或旧版只有汇总计数的计划，不具备这套来源证明；须先补齐计划和受支持的测试入口。

## 被测对象与独立执行

直接检查和独立test会话各自获得全新的候选副本及产物目录。运行器记录源文件摘要、实际加载或构建来源、执行结果及产物摘要。CMake从当前候选重新配置与构建，检查编译来源及CTest实际目标；禁止用原项目或旧build的结果冒充新候选。工具安装路径可以是绝对路径，产品输入与被测产物必须通过来源核验。

独立test会话只可在分配的产物目录写构建和测试产物，源副本在可写根之外，所有原候选输入仍须保持不变。审核与诊断会话继续只读。新候选或验证基线变化后重新执行完整必需检查，不复制旧PASS。运行器在实际命令输出中记录结构化结果摘要，控制器在接收报告时核对；执行后改写结果也会拒绝。日志、JSON逐项结果及产物来源记录与候选关联，并在报告批准前核验未被修改。

该协议不证明任意测试本身覆盖了全部业务语义，独立需求/计划审核仍需核对AC映射。现有执行器不自动获得设备刷写、网络操作、外部部署权限；缺少HIL或专有验证协议时应交L1协调所需能力，不能用主机样例替代硬件验收。

## L2调度L4恢复设施

计划可声明`verification.facility_recovery.actions`。每项有唯一`id`、`kind`和`description`；`kind=command`另提供完整`command`参数数组，`kind=retry`仅表示已批准的瞬时故障重试。动作需在独立计划审核中确认用途、范围及副作用，不以文字声明取得外部设备、网络或交付权限。

L2分类为设施或证据问题后，在结构化分析的`facility_actions`列出已批准动作ID，并提交完整`solutions`、收益、验证步骤、资源和权限缺口。没有动作ID、动作未获批准或存在权限缺口时进入`DECISION_PENDING`，由L1处理方案/授权，不能只循环原失败命令。

命令动作由本地L4运行器按原参数执行，工作目录为控制区的`run/facility-workspace`。参数仅支持`{candidate}`和`{facility}`根路径占位符。测试通过`REQPILOT_FACILITY_DIR`读取已批准的本地设施文件；设施文件不作为产品来源证明。不能在此修改产品源码、候选、测试判定逻辑或已保存证据。该直接命令入口与已批准测试入口一样，不是阻挡同账户恶意脚本的操作系统安全沙箱；独立审核必须检查实际命令及代码。

设施恢复每轮计入原设施重试额度，保留命令、日志、L2方案与候选身份。失败回L2分析；结果无法核实保留在途记录并交L1核对，不重放。恢复完成后重新运行全部必需验证。超出本地设施能力的恢复，由L1组织修订或获取所需授权；不会自动安装系统工具、重启设备或执行部署。

自动L3修复与经L1批准的修复使用同样交接内容：原失败证据、L2完整方案、验证步骤、资源、权限边界和允许路径；L3无需猜测被省略的方案。

## 旧任务迁移

升级保留原授权、需求、已完成实现、账本和失败历史。旧计划缺少测试契约时先由L1修订并独立重审，不能仅升级运行器就把旧计划当作满足新门禁。未决操作须先核实；最终报告不撤销，消费记录不清零。详见[任务升级](task-upgrades.md)及[完整流程与恢复](flow-recovery.md)。
