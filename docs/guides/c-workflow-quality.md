# C工程生成与审核一致性

入口文件负责程序入口、初始化调用和顶层流程组织，可保留少量入口辅助函数；具有独立职责的硬件驱动、协议处理和业务算法放对应.c/.h。不能把完整驱动集中在main.c，也不按函数数量或文件行数机械拆分。内部函数保持static，公共头只公开必要接口，状态和内部宏留在模块实现及私有头文件；保留资源所有权、调用顺序、错误处理和行为，不新增空模块、无意义包装或无关抽象。

公开函数在.h声明上方保存完整Doxygen调用契约，@param及@return/@retval只在该契约处维护；.c定义上方保留Doxygen，用@details/@par说明步骤、状态、副作用和失败处理，并用@see指向对应头文件。参数和返回条件可用普通段落准确说明，不重复机器标签，不对同一声明/定义函数使用自引用@copydoc。无头文件声明的内部函数在定义处完整记录真实参数和返回。不能删掉实现说明或关闭告警来换取通过。

明确违反已采用规则交L2分析并派L3修复；非必要结构建议由L2评估收益和范围交L1决定，不作为自动修复阻断；规则或检查工具冲突先由L2调查，交L1澄清规则或安排L4验证设施修复，不让L3反复修改产品碰运气。所有非成功结案仍须L1评估。

## 查看任务实际使用的规则

安装3.23.0主包后，workflow_status和dot_status的workflow_runtime.coding_standards显示任务版本、项目规范revision、本机已校验可用版本的新增/修改/删除条目，以及候选审核摘要。available_verified表示已校验的本地版本，不冒称刚查询过远端最新版。差异仅提示L1评估适用性，不制造任务失败或自动升级。

新运行器的coding_standards返回当前规则摘要、批准/候选规则是否匹配、当前候选的独立审核记录状态；NOT_RUN和STALE不能当PASS。旧运行器没有摘要时返回null，不虚构审核。审核状态只表示已有绑定记录，不重跑检查、不代替最终验收。

已确认任务仍固定旧版本。采用新版须按既有workflow_updates升级预检与原生确认机制，L1审核受影响基线，保留旧证据、消耗和权限。仅更新插件不会自动重写已开工任务或产品。新的版本差异展示位于主包bootstrap，已有安装须更新主包才能显示，不能仅靠后台运行时更新。

## 验证范围

真实Doxygen验证同时输入.c/.h：合法声明契约+实现说明通过，缺参数、错参数、声明/定义重复参数及声明内重复参数被拒绝；保留警告和完整XML，不降级检查。模块职责由独立审核结合实际候选判断，不用函数数量或Doxygen PASS冒充结构合规。

小型LED模块示例位于standards/embedded-c/v1.3/doxygen/module-example：main只组织流程，pattern计算颜色，driver通过标准输出模拟驱动边界。真实Doxygen同时检查五个源/头文件；这是主机教学示例，不代表ESP32固件或实机验收。
