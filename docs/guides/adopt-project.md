# 接入真实产品项目

## 分开三个存放位置

本规范仓库存流程文本、模板与通用策略。产品代码仓库存实现及开发自测。实际控制仓库/证据存储承接受保护策略、独立验收、批准及原始证据；不能因文件在不同目录就宣称具备权限隔离。

## 首次接入

1. 让用户指定产品仓库和试点功能。记录采用的本规范commit和VERSION，避免任务期间随main漂移。
2. 将 [项目上下文模板](../../templates/project-context.json) 的副本放到项目约定的控制位置，填写真实值；能力未实现保留NOT_IMPLEMENTED。
3. 用 [产品规格](../../templates/product-spec.md) 和 [验证计划](../../templates/verification-plan.md) 建立双基线。明确每个角色及授权人的真实身份，角色名不等于认证身份。
4. 由授权人明确实现范围、路径和预算；适配器、审批、证据、CI的缺口纳入L2任务，而不是把示例状态写成已通过。
5. 产品仓库若已有AGENTS.md，先读现有约束，再加入规范路径/固定版本引用；不要直接覆盖现有规范或全局设置。
6. 本项目文件不自动触发Agent工具加载。要求Agent在工作前显式读取入口，并回报读到的文件和对象版本。

## 最小任务与可信审批

草案任务用 [任务模板](../../templates/task-draft.json)。派发前必须由实际控制器校验有效开工包、L2身份、依赖、唯一活动尝试及允许路径。模板中任何字符串都不能代替认证批准。

## GitHub公开内容

此规范项目可单独上传。真实审批回执、凭证、私有产品代码、硬件身份及原始运行数据应按项目权限存放，不要把它们混入公开规范仓库。仓库内的内容清单只是本地完整性检查，不是签名或可信来源证明。
