# 自动更新与会话连续性

从3.4.1起，ReqPilot由稳定的Harness入口和按版本保存的工作流组成。当前应安装3.5.0并按宿主要求加载ABI3入口，让原会话获得支持任务迁移的`workflow_updates`工具。之后兼容更新可以在同一会话的工具调用之间启用，不再每次下载安装包、重启对话。这里更新的是ReqPilot工作流，不是DeepSeek Harness本身。

## 用户怎么使用

安装后默认开启。使用工作流工具时，后台至多每6小时检查一次[正式发布](https://github.com/Merrychen-CMY/ReqPilot/releases/latest)，无人使用时不另起常驻进程。可以对L1说：

- “检查ReqPilot更新，并告诉我当前任务实际使用的版本。”
- “关闭自动更新。”或“重新开启自动更新。”

L1调用`workflow_updates(action)`，常规action为status、check、enable或disable；已开工迁移另用upgrade_preview、upgrade和upgrade_recover，详见[任务升级](task-upgrades.md)。检查只访问固定仓库，不发送项目资料、GPT模型密钥或产品记录，不调用付费API。关闭后也不执行手动check的网络请求；重新启用后下一次工作流活动触发检查。不要把更新失败当作产品任务失败。

状态中的READY表示新版已下载、校验并通过工具接口检查。实际执行版本以每次工作流结果的`workflow_runtime.version`和`manifest_sha256`为准；`task_pinned:true`表示任务绑定原确认或最近一次已批准迁移的版本。安装管理页显示的是稳定入口版本，可能与工作流版本不同。

## 哪些更新不需要重开会话

| 情况 | 行为 |
| --- | --- |
| 尚未确认开工，更新属于同一主版本、ABI和工具接口 | 下载完成后的下一次工具调用自动采用新版；新规则随工具结果给L1，无需重开会话。 |
| 已做环境检查或生成待确认摘要，但尚未开工 | 采用新版后旧环境/摘要因版本哈希变化而失效。L1保留用户资料，重新检查环境和整理摘要，再集中确认，不能用旧摘要直接开工。 |
| 已确认开工且无活动/未知操作、非终态 | 默认保留原版本；3.5.0可在原会话预检并经原生确认迁移，保留记录及消耗，重新审核验证。 |
| UNKNOWN、最终报告或操作仍在执行 | 保持原版本，不通过升级清除阻塞或撤销报告。 |
| 只有下载/导入/校验失败 | 不发布新版本指针，保留原可用版本。失败不会制造产品UNKNOWN或调用DOT。 |
| 新增工具、主版本或入口ABI变化 | 标记HOST_UPDATE_REQUIRED，需要一次宿主插件升级；不声称任何更新都可热加载。 |

已开工任务不会因为自动更新而要求重开对话，但也**不会自动获得新版本的运行器修复**。3.5.0提供[受控任务迁移](task-upgrades.md)，经准确预检和原生确认后在同一对话切换；不能清除UNKNOWN、撤销最终报告或重置次数。

3.3.x及更早版本没有自动更新入口，也没有事先保留完整运行版本。直接覆盖旧安装不能保证旧任务继续执行。旧任务原版本缺失或损坏时报TASK_RUNTIME_MISSING_OR_DAMAGED，保留全部记录；需要维护者核对并恢复准确旧版本，不会猜测兼容性或改写确认摘要。未开工会话可安装3.5.0后继续整理已有需求，但需重新核对环境和摘要。

## 实现与失败恢复

缓存放在用户目录`.ai-programming-workflow/updates/runtimes/<MANIFEST摘要>/`；密钥仍由Harness凭据服务管理。每个版本保存完整规则和运行器，每次调用验证清单内容后再加载。已确认任务从原confirmation.json及经批准的runtime-upgrades.json迁移链读取有效版本摘要，重启后仍选择同一份缓存。下载检查不写任务数据；单独批准的迁移按事务更新状态及迁移日志，不改原确认。缓存不自动清理，以免破坏历史任务恢复。

来源固定为Merrychen-CMY/ReqPilot的正式GitHub Release。公开资产优先通过[GitHub官方最新资产链接](https://docs.github.com/en/repositories/releasing-projects-on-github/linking-to-releases)读取stable通道信息。私有仓库或公开下载不可用时，通过本机已有Git凭据只读访问此仓库的GitHub API，避免匿名REST接口限流。只接受固定命名更新资产，限制请求时间、下载/解压大小、路径及文件集合，拒绝路径越界、符号链接、大小写别名、内容摘要不符和工具契约变化。不运行安装脚本，不执行远端命令，不自行修改Harness配置。SHA-256证明内容一致；发布者信任来自固定GitHub仓库和HTTPS，不是独立签名审批服务，也不防同账户恶意进程。

下载和准备使用临时目录，验证、模块导入及接口检查均通过后才原子切换可用版本指针。更新锁只保护缓存安装；遇到并发安装返回UPDATE_BUSY，保留任务和原版本。若宿主异常退出留下install.lock，应先核实该文件记录的安装进程已停止，再由维护者处理更新锁；不能清除产品interrupted.json。已启用版本后来损坏时阻止运行，不自动换版本执行。更新前失败可保留旧版；执行产品动作后的异常仍按原UNKNOWN规则处理，更新器不回滚产品动作。

宿主依据：本机DeepSeek Harness0.2.2-rc.3的dsh-agent-preset-registry和plugin-manager随包README/源码。现有Agent保留preset修订及提示词；HMR和包替换不保证旧会话整体换版。因此使用稳定工具入口，在每次调用前选取不可变运行版本，并返回该版本原生说明与完整规则的读取路径。规则读取每段最多6000字符，L1必须沿next_offset读完，避免宿主裁剪长工具结果。没有修改宿主内部Agent状态或强制清空上下文。工具结果能提供新规则，不保证模型绝对遵守，独立审核与控制器门禁照常保留。

## 维护者如何发布

1. 修改代码、文档、版本与清单；同ABI更新必须保留原工具名称、参数名及其语义，不可借兼容更新改变确认/授权含义。
2. 更新`docs/releases/<版本>.md`。用`python scripts/package_release.py --output-dir <仓库外目录>`构建本地安装包、完整运行包和摘要信息。
3. 提交并推送代码，再推送与VERSION一致的`v<版本>`标签。验证工作流全部通过后，独立发布作业创建正式Release和三个资产。普通main提交不会成为自动更新源。
4. GitHub的发布仓库访问权限必须受保护。当前入口下载更新支持ABI3和同一主版本；已确认ABI1/2缓存可继续原版本运行；更新器自身、稳定入口、新工具或宿主接口调整须提高入口ABI并发布需要安装的版本，说明原因。内置工作流更新不会替换已加载的入口/更新器自身代码。

查看[3.5.0验证边界](../reports/3.5.0-validation.md)。模拟同会话切换、真实本地Python管道、远端发布检查和真实Harness聊天验证分别记录，不相互替代。

## 私有仓库的登录

你的ReqPilot仓库可以保持私有。3.4.1入口复用Git Credential Manager等本机Git凭据助手已保存的GitHub登录，不索取聊天中的密钥，也不把GitHub凭据写进ReqPilot设置。仅向api.github.com上本仓库的精确只读API地址临时发送凭据；重定向到下载CDN时不携带凭据。更新检查不修改远程仓库。

没有可用Git登录时返回UPDATE_GITHUB_LOGIN_REQUIRED，保留当前版本和任务。先通过Git/Git Credential Manager的正常登录流程登录有本仓库读取权限的账号，再让L1检查更新；插件不会弹出自动登录或询问GPT密钥。凭据助手最多等待8秒，禁止交互提示；它不是新的凭据库。仅需读取仓库和发布资产的权限。

3.4.0首版更新器仅支持公开下载，不能自动访问本私有仓库。当前首次安装应使用3.5.0（入口ABI3），3.4.x已安装用户需要这一次入口升级。ABI3保留已确认并缓存的ABI1/2工作流，默认按原摘要运行；经批准的3.4.0/3.4.1任务可迁入3.5.0。仍不自动迁移3.3.x旧任务。

3.6.0为ABI4，需要宿主更新安装包才能增加初始化恢复入口。旧ABI3自动更新应提示HOST_UPDATE_REQUIRED。初始化恢复与普通升级独立，见[专用指南](initialization-recovery.md)；旧会话必须实际加载新入口后才能调用。

3.13.3另修复宿主启动层的已完成开工前审核恢复路由。要使用该修复，须安装3.13.3主插件包并让Harness重新加载插件；只下载兼容运行包不能改变已加载的启动层。维护恢复保持任务固定版本，之后仍须原生任务升级，不通过更新清除中断。


加密环境补充（3.18.0）：安装 ABI12 主包后，按[加密环境指南](encrypted-environment.md)诊断读/复制/替换及各工具内容视图。旧任务保留原ID与记录；未决操作先核对并原生恢复，再版本升级。文件环境问题由L2调查、L1评估，不自动最终结案。
