# 加密环境兼容与原任务恢复

适用于 ReqPilot 3.18.0 / ABI12。企业透明加密可能让不同程序读取同一文件时得到不同内容；不限于 C/H 示例。兼容处理不要求关闭、卸载或绕过加密软件，不提供解密密钥或解密算法，不改变原任务职责、授权或验收要求。

## 正常使用

1. 安装最新主包并让 Harness 重新加载插件，保留原会话 ID、任务目录、配置和凭据。旧 ABI11 主入口不能靠运行文件自动更新获得此修复；无需新建产品任务。
2. L1 调用 `workflow_updates(action="diagnose")`。此入口不依赖产品运行时完整性校验，不调用 GPT，不运行产品命令，只在工作流目录创建、检查和清理随机探测文件。配置本身无法读取时返回明确文件错误，不冒充诊断通过。
3. 新任务按原顺序配置模型与密钥、检查环境、沟通需求、集中确认后推进。环境检查加入 JSON、Markdown、C/H、Python、JS、EXE、BAT、CMD 的读、复制、替换及内容摘要核对；探测文件都是不可执行的普通文本，从不运行它们。
4. L2 在实际产品目录继续核实各个使用者能否读取获批输入。Python 可读不等于 Codex、编译器、CMake 或 Doxygen 可读。按授权进行真实读码、构建和验证；只读调查不得顺便实现产品。不同结果记录为环境证据，提交 L1 评估处理方案。

## 文件内容与完整性

- 插件先使用 Node 正常读取。发现明确的加密封装，或已记录摘要不匹配时，尝试配置页指定的 Python，通过同账户、系统允许的普通文件接口读取。固定辅助程序只使用标准库，不执行项目脚本、不启动 shell、不修改加密策略。
- 对有摘要的文件，只有全部匹配原摘要才可采用该内容视图；不能删除清单条目、忽略 C/H、把密文重新登记成正确版本。切换只影响当前工具调用，不全局修改其他会话。结果记录所用读取程序及差异路径。
- 不识别的加密格式不会被猜测解密。已有摘要可用于识别内容不一致；没有可靠摘要的任意二进制文件不能仅凭看起来可读就宣布正常。工具实际读取及验证仍是必要证据。
- 控制记录写入后回读核对；短暂占用时只对同一待保存文件重试替换，最多六次尝试，累计等待约 1.55 秒。失败保留原记录和临时文件。不会重新调用 GPT、重跑命令、重派实现或清零消耗。
- 候选快照分别比较路径属性与路径属性、句柄属性与句柄属性，避免 Windows 合成执行位、物理/逻辑长度差异造成误报；仍核验文件身份、读取稳定性、逻辑内容摘要、复制前后完整清单和模式。真正变化仍拒绝生成候选。

## 错误如何处理

| 状态/代码 | 含义 | 下一步 |
|---|---|---|
| `FILE_ENCRYPTED_VIEW` | 当前读取程序获得明确的加密封装 | L2 核实允许的读取程序与实际消费者；L1 协调 |
| `FILE_CONTENT_MISMATCH` | 各可用视图均未匹配原摘要 | 保留文件和原摘要，调查内容变化，不刷新摘要放行 |
| `FILE_CONTENT_CHANGED` | 同一读取期间内容变化 | 等待合法写入结束后重新检查；不采用半份内容 |
| `FILE_ACCESS_DENIED` / `FILE_PROVIDER_UNAVAILABLE` | 权限不足或配置的 Python 无法运行 | L2 检查路径、版本、可用性与允许的操作方式 |
| `FILE_WRITE_VERIFY_FAILED` | 写入后的实际内容不一致 | 保留现场，检查存储和过滤软件，不自动重做产生结果的操作 |
| `FILE_REPLACE_BLOCKED` | 记录替换持续被占用或拒绝 | 保留临时文件及旧记录，按恢复流程核对 |
| `FILE_ENVIRONMENT_BLOCKED` | 原生入口无法可靠读取必要文件 | 当前任务状态未核实；仅暂停受影响流程，不自动最终结案 |

以上问题统一由 L2 提交已核实事实、可行方案及权限缺口，L1 评估后继续。文件错误不会证明先前操作没有副作用。存在未决操作时保留保护；所有非成功结案仍须 L1 明确评估。

## 已中断的原任务

先诊断并核对任务状态、原确认、API 账本、进程记录、宿主工具收据和产品变更。不要删除 `interrupted.json`、研究记录或临时文件，不手工将 UNKNOWN 改为 PASS，不把 `.tmp` 直接覆盖成正式结果。

规划前的 `l1_approve`、`dot_plan`、`dot_research` 中断可由新主包调用经校验的维护运行时先由 `l1_prepare_recovery` 保存有证据的恢复方案，再进行 `workflow_recover_operation`，仍须原生恢复确认；普通工具保持旧版本固定。完成后按提示 `upgrade_preview` → 原生 `upgrade`，再独立重审受影响基线。无法核实进程或副作用时继续调查，不能因安装新版就自动解锁。

直接 `host_tools` 仅查询当前工具登记表，本来就没有独立 worker。恢复器核对原始记录类型、参数和摘要后，不再强求一个不存在的 worker PID；宿主外层进程与其他活动仍须核实。此规则不适用于 `host_call`、命令、子智能体或后台作业，不把尚未提交的查询结果冒充成功。原 UNKNOWN、失败、消耗和恢复记录全部保留。

## 能力边界与验证范围

如果操作系统不允许任何可用程序读取明文，或 Harness/Node 连插件 JavaScript 入口本身都无法加载，插件无法自行取得这些权限。此时保留任务并报告具体阻碍；不能声称插件可解决所有企业加密策略，也不要求用户反复重建任务。

本版本验证包括真实本机文件/管道、模拟不同程序内容视图、占用故障注入、快照及恢复拒绝测试。用户报告所在的 ONEDLP 电脑不在当前会话可操作范围，未在该机器完成实机验证；安装后首先执行诊断，必要时根据实际错误继续处理。
