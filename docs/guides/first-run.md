# 首次闭环

目标是用一个真实小任务验证成功主线和失败回流。先单任务、单候选运行、单块板卡；无法提供所需硬件时保持相应检查BLOCKED。

1. **建上下文**：填写项目路径、目标分支、工具固定版本、身份、权限、设备和现有接口；列出尚未实现的能力。
2. **双L1**：Product L1确认目标、非目标、AC；L1-V建立每条AC的检查、预期、证据、环境及预算。完成门1授权。
3. **L2派单**：拆一个任务，绑定起点、路径、依赖、预算和交付物；记录真实run_id。
4. **L3实现**：修改授权代码并自测，停止写入；受控构建生成不可变候选，门2准入。
5. **验证实例**：L1-V绑定候选并取得有效授权，V0通过后L2调度L4执行必需检查。
6. **真实失败回流**：注入一个实现缺陷。L4报L2，L2确认根因派L3；新候选、重绑L1-V和独立重验。保留旧FAIL。
7. **其他路由**：分别演练错误测试预期、设施中断、需求/AC变化和交付目标漂移。核实对应处理层和失效规则。
8. **交付**：门3通过后L5汇总AC/风险/历史与申请，门4由授权人批准，守卫核验一次性动作，保存回执。

第一阶段可以人工承担L2并手动传递任务，但版本、权限、证据和门禁条件不能省略。随后依次接入候选/测试/证据、门禁、持久化调度与恢复、工具桥接，最后再启用并发。

完整操作和48项上线拒绝测试见 [完整验收章节](../reference/21-acceptance.md)、[拒绝测试清单](../../policy/rejection-tests.json)。静态脚本通过不能把这些测试改成已执行。
