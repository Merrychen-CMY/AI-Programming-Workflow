# 首次跑通

1. 用户把一个小任务的原始目标、参数、环境、项目位置和限制交给L1；L1集中问清缺少的关键事实。用户不审核中间需求/计划。
2. L1或安装维护者按 [接入指南](l1-harness.md) 配置本地MCP、API模型/环境凭据、Codex和真实测试入口，固定有限委托。未接通就报告缺口。
3. L1生成需求和内部L1-V验证要求，调用dot_plan取得GPT计划，dot_initialize固定起点；调用l1_approve分别审查批准需求和计划。核对独立审查记录与delegated_l1身份。
4. L1调用dot_run，检查独立开发、真实测试命令、独立测试与审核在同一候选上留下证据；嵌入式C增加真实Doxygen与华为逐条证据。
5. 试验至少一个实现失败：必须先经DOT根因分析，再派L3，产生新候选重验。再检查需求/测试计划问题会返回L1而不是弹出用户中间审批。
6. 成功或失败都由L1核查报告并调用l1_submit_report，然后交用户审核。缺证据不能成功；失败确认后停止。只验证本地流程时不执行发布或设备刷写。

运行以下仓库自检可先核对接口/状态拒绝逻辑，但不能代替上述真实联调：

```powershell
python scripts/validate_repo.py
python -m unittest discover -s tests -v
```

拒绝重点：无委托、原始目标漂移、扩大范围/预算、同会话自审、缺/旧证据、API超限/失败重放、L1代审最终报告。真实结果另存产品证据，不把48项参考场景默认改为PASS。
