# 首次跑通

1. 用户向L1提供需求、参数、环境与资料；L1填写 [需求文档](../../templates/requirements.md)，用户审核具体版本。
2. DOT核对产品位置和工具能力，编排一个小任务，填写 [执行计划](../../templates/execution-plan.md)：方案/依赖、独立开发/测试/审核、必需检查、预算及风险。用户审核计划后才开始实现。
3. 独立开发会话实现与自测，冻结候选；另一会话组织实际测试，第三个会话独立审核代码和证据。
4. 失败先回DOT分析根因，范围内有限修复后形成新候选并重验。普通修复不反复审核需求；AC或需求变化先由L1提交新版本审核，计划实质变化重审计划。
5. 成功或重试耗尽都由DOT生成 [最终报告](../../templates/final-report.md) 供用户审核。必需项缺失为未完成，不得假称通过。
6. 成功报告批准后进入DELIVERY_READY；失败报告确认后为BLOCKED。继续失败工作须重审必要计划和追加预算，计数不清零。
7. 外部合并/发布/刷写另核授权与真实结果。本地运行器未实现外部交付，不能自动将可交付写为已交付。

本地运行步骤见 [运行器指南](local-runtime.md)。首次至少演练未批准计划不能开工、一次真实失败回DOT、新候选独立重验、耗尽提交报告四种情况。软件任务无需硬件；AC包含HIL时缺设备就阻断依赖动作。

原 [48项拒绝测试](../../policy/rejection-tests.json) 用于正式系统/HIL接入，仍是NOT_RUN，不能拿仓库自检当真实验收。嵌入式C规范及设备适用性按 [接入清单](../../standards/embedded-c/adoption.md) 确认。
