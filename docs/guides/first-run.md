# 首次跑通

1. 按[原生插件指南](l1-plugin.md)安装并新建“ReqPilot · 需求领航”会话；先在配置页填写模型和密钥，主动测试API。
2. L1调用workflow_check_environment检查基础环境，无需项目需求。必需条件失败/未知时先解决缺口，不继续收集需求。检查不调用GPT、不派工。
3. 基础环境通过后，用户沟通小任务的原始需求、参数、已有环境和限制；L1补齐九项信息，复核项目特有环境并固定项目指纹与有限预算，用户集中确认开工。
4. L1生成需求和内部L1-V验证要求，调用dot_plan取得GPT计划，dot_initialize固定起点；调用l1_approve分别审查批准需求和计划。核对独立审查记录与delegated_l1身份。
5. L1调用dot_run，检查独立开发、真实测试命令、独立测试与审核在同一候选上留下证据；嵌入式C增加真实Doxygen与华为逐条证据。
6. 试验至少一个实现失败：必须先经DOT根因分析，再派L3，产生新候选重验。再检查需求/测试计划问题会返回L1而不是弹出用户中间审批。
7. 成功或失败都由L1核查报告并调用l1_submit_report，然后交用户审核。缺证据不能成功；失败确认后停止。只验证本地流程时不执行发布或设备刷写。

运行以下仓库自检可先核对接口/状态拒绝逻辑，但不能代替上述真实联调：

```powershell
python scripts/validate_repo.py
python -m unittest discover -s tests -v
```

拒绝重点：无委托、原始目标漂移、扩大范围/预算、同会话自审、缺/旧证据、API超限/失败重放、L1代审最终报告。真实结果另存产品证据，不把48项参考场景默认改为PASS。

插件还须拒绝：配置未完成就检查基础环境、基础检查未通过就准备需求、重查失败/中断沿用旧PASS、未确认就调用DOT、取消/跳过确认、确认期间摘要/模型/项目变化、必需环境未知、模型伪造会话身份、重启后重放UNKNOWN、最终报告被改写。检查结果记录在真实任务中；模拟测试不能填入产品PASS。
