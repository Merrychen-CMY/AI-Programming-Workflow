# 核心规则

规范性共同入口为 [AGENTS.md](../AGENTS.md)，默认机器策略为 [simple-flow.json](../policy/simple-flow.json)。

1. 顺序为配置模型和密钥 → 检查环境 → 沟通原始需求 → 集中确认开工 → L1 自动推进 → 用户审核最终报告；L1是唯一入口。
2. L1在原始委托内生成、审核并批准需求和计划；保留独立审查，使用delegated_l1记录，不伪装用户身份。
3. GPT就是DOT；API提出计划、调度与根因分析，本机控制器派发独立开发、测试、审核。
4. 所有L4/L5问题先到L2，再按根因派发。实现缺陷回L3，需求回L1，验证计划回L1内部L1-V，设施回L4。
5. 范围内变更由L1重新批准；用户目标、权限、总上限和截止时间不可自行扩大。当前额度由L1自动制定和调整；额度耗尽先评估，需扩大边界先申请用户批准，无可行方案才形成最终报告。
6. 固定候选、真实证据；代码/构建变化重新验证，不复用旧PASS、不删除失败。
7. 尝试、审查、修订、API、时间均有限；重启不清零，UNKNOWN不盲重放。
8. DOT汇总，L1核查并提交最终报告；L1不能批准用户最终报告、不能升级失败结果。
9. 成功报告用户批准后仅可交付；外部动作核对授权和回执，本运行器不执行发布/刷写。
10. 华为逐条C规范及Doxygen细则保持完整，华为优先；工具检查和语义审核都要有证据。
11. 本机文件/会话不是强权限隔离或签名审批服务，正式保护继续生效。
12. L1与DOT应用[合作沟通约束](guides/l1-dot-communication.md)：结论/请求优先，保留必要上下文、失败与证据；事实/推断/未知分开，沉默/收到不授予权限，原工具和状态机不变。
13. L1面向用户按[选择性表达规则](guides/l1-user-expression.md)提供清楚的理解、建议和最终结论；原始需求、验收、授权和证据优先，失败与未知不得美化，不改变结构化回执或增加用户审批。

原生插件的[开工策略](../policy/onboarding.json)要求一次集中确认：配置/环境检查及九项需求完整后，由真实用户确认准确摘要；之后继续既有L1代理审批。新引导状态不代替运行状态、预算或候选规则。

规划子状态NEEDS_INFO允许在同一任务内补齐事实；UNKNOWN保留禁止重放，最终报告不自动重开。原开工记录与授权不变，l1_add_facts追加可审查版本并扣原修订预算，需求/计划新基线经独立审查和L1批准才可执行。见[澄清指南](guides/clarifications.md)。

完整返回的草案纯校验拒绝使用PLAN_REJECTED/COMPLETED_REJECTED，仅清除当前已完成操作的在途标记。实现次数是全任务L3派工累计上限，初次与修复共同计数；独立验证保持独立。机器约束见[规划策略](../policy/planning.json)，恢复边界见[计划拒绝指南](guides/plan-rejections.md)。

新动态任务以[资源策略](../policy/resources.json)和[实施指南](guides/adaptive-resources.md)为准：用户确认目标/权限/总上限/截止时间，L1管理当前额度。桥层BUDGET_REVIEW_PENDING与AUTHORIZATION_PENDING保留runtime_state；恢复不重置累计消耗，扩大范围须原生用户授权并独立重审。历史固定预算示例不替代当前任务授权。
