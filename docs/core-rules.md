# 核心规则

规范性共同入口为 [AGENTS.md](../AGENTS.md)，默认机器策略为 [simple-flow.json](../policy/simple-flow.json)。

1. 顺序为配置模型和密钥 → 检查环境 → 沟通原始需求 → 集中确认开工 → L1 自动推进 → 用户审核最终报告；L1是唯一入口。
2. L1在原始委托内生成、审核并批准需求和计划；保留独立审查，使用delegated_l1记录，不伪装用户身份。
3. GPT就是DOT；API提出计划、调度与根因分析，本机控制器派发独立开发、测试、审核。
4. 所有L4/L5问题先到L2，再按根因派发。实现缺陷回L3，需求回L1，验证计划回L1内部L1-V，设施回L4。
5. 范围内变更由L1重新批准；用户目标、权限、总上限和截止时间不可自行扩大。当前额度由L1自动制定和调整；额度耗尽先评估，需扩大边界先申请用户批准，无可行方案才形成最终报告。
6. 固定候选、真实证据；代码/构建变化重新验证，不复用旧PASS、不删除失败。
7. 尝试、审查、修订、API、时间均有限；重启不清零，UNKNOWN不盲重放。
8. DOT汇总，L1核查并提交最终报告；L1不能批准用户最终报告、不能升级失败结果。
9. 成功报告用户批准后仅可交付；外部动作核对授权和回执，本运行器不执行发布/刷写。
10. 华为逐条C规范及Doxygen细则保持完整，华为优先；工具检查和语义审核都要有证据。
11. 本机文件/会话不是强权限隔离或签名审批服务，正式保护继续生效。
12. L1与DOT应用[合作沟通约束](guides/l1-dot-communication.md)：结论/请求优先，保留必要上下文、失败与证据；事实/推断/未知分开，沉默/收到不授予权限，原工具和状态机不变。
13. L1面向用户按[选择性表达规则](guides/l1-user-expression.md)提供清楚的理解、建议和最终结论；原始需求、验收、授权和证据优先，失败与未知不得美化，不改变结构化回执或增加用户审批。
14. 按[执行范围约束](guides/execution-scope.md)先定结果、对象、保留约束和AC，仅做严格必要的最小改动；解释/诊断/评审不改代码、不跑测试。已授权验证继续按计划执行，非验收建议交L1转用户决定，不自动扩展机制或修复范围。
15. L1每次实际需求/计划审核及最终提交生成`.md`报告，在当前聊天提供文件卡与可打开链接，失败报告也保留。卡片在本轮结束后由宿主显示，审核前先给链接；文件不替代证据、批准或最终用户审核，交付事件失败不得声称卡片已展示。
16. 独立执行会话连续120秒无可见进展且无命令运行时，L2运行器在同一会话询问“你正在做什么？”，只需公开进度与最小下一步；不索取思维链、不把RPC送达当回复、不延长总超时/额度。L5由DOT承担，不虚构独立会话。

原生插件的[开工策略](../policy/onboarding.json)要求一次集中确认：配置/环境检查及九项需求完整后，由真实用户确认准确摘要；之后继续既有L1代理审批。新引导状态不代替运行状态、预算或候选规则。

规划子状态NEEDS_INFO允许在同一任务内补齐事实；UNKNOWN保留禁止重放，最终报告不自动重开。原开工记录与授权不变，l1_add_facts追加可审查版本并扣原修订预算，需求/计划新基线经独立审查和L1批准才可执行。见[澄清指南](guides/clarifications.md)。

完整返回的草案纯校验拒绝使用PLAN_REJECTED/COMPLETED_REJECTED，仅清除当前已完成操作的在途标记。实现次数是全任务L3派工累计上限，初次与修复共同计数；独立验证保持独立。机器约束见[规划策略](../policy/planning.json)，恢复边界见[计划拒绝指南](guides/plan-rejections.md)。

新动态任务以[资源策略](../policy/resources.json)和[实施指南](guides/adaptive-resources.md)为准：用户确认目标/权限/总上限/截止时间，L1管理当前额度。桥层BUDGET_REVIEW_PENDING与AUTHORIZATION_PENDING保留runtime_state；恢复不重置累计消耗，扩大范围须原生用户授权并独立重审。历史固定预算示例不替代当前任务授权。

插件自动更新只改变未开工会话后续选用的兼容运行版本；已确认任务默认由MANIFEST摘要固定代码和规则；可按[任务升级规则](guides/task-upgrades.md)预检并经原生用户确认迁移。迁移保留原授权、历史及已完成任务，失效旧审批/候选并重新审核验证，不能清零消耗或解除UNKNOWN/终态。详见[更新规则](guides/automatic-updates.md)。

初始化的专用恢复见[初始化恢复规则](guides/initialization-recovery.md)：仅处理未提交运行状态的本地初始化，准确原生批准后归档部分文件与中断标记；允许明确接受新基线，随后重新规划和独立审核。原确认及累计消耗保留，产品UNKNOWN和终态不得借此解锁。

API请求异常采用[API评估与恢复](guides/api-recovery.md)：先L1评估，必要时原生确认下一次请求；原UNKNOWN和消耗不改写，终态及产品执行UNKNOWN不恢复。

正常开工采用[原始证据交接与紧凑回执](guides/normal-start.md)。审批前置条件不满足是已完成拒绝，不能冒充执行中断；真正未决操作仍保持原保护。


3.9.0调查规则：问题统一交L2调查；尚未查明原因不得自动结案。取消根因分类unknown，needs_analysis表示L2调查待办，缺资料、权限或资源交L1解决。L1在授权内推进，越界主动申请用户原生授权，有必要继续解决时保留任务；仅评估无可行方案、用户结束或无法调整的全任务限制才提交最终报告。材料超限返回NOT_SENT/COMPLETED_REJECTED，不产生本次API消耗或最终UNKNOWN；完整证据保留并分页读取，摘要明确标注。操作执行状态仍如实记录；只读调查不能清除未决产品操作或重放写入。详见[调查与材料处理](guides/investigation.md)。

非成功结案规则（3.10.0）：L2 可以暂停操作、提交问题和建议终止，不能直接把整个任务判为最终失败。遇到问题先根据证据在现有权限内思考解决方案，记录已考虑方案、预计收益、核验步骤、资源及权限缺口；可执行的修复仍按原分工派 L3/L4。证据不足应提出有边界的调查方案，不能以“未知”替代分析并结束。超出 L2 权限时，将方案交 L1 评估；L1 在授权内协调，越界主动向用户申请。所有非成功结案（FAILED、INCOMPLETE、UNKNOWN）都必须先经过 L1 明确评估。控制器自动错误及旧预算耗尽只暂停，不生成最终报告。l1_stop 的 reason 使用 templates/l1-closure.example.json 所示 JSON 字符串，记录方案、证据、权限、资源和终止依据；普通理由文本会被拒绝且不结案。成功验收门禁、原始失败、累计消耗和未决操作保护保持有效。详见 docs/guides/l1-closure.md。

3.11.0流程顺序与恢复：新原生任务强制动态额度。开工确认并分配额度后，先l1_prepare_requirements → l1_approve(requirements)，通过后才dot_plan → dot_initialize → l1_approve(plan) → dot_run。初始化承接原需求独立审核及消耗，不重复审核。DECISION_PENDING使用dot_investigate继续只读分析，L1用l1_resume_decision选择有证据的恢复方案；旧操作未核实时先经原生恢复核对，不能重放。修订保留不受影响的已完成实现，候选与验证随基线重新核验。开工前后报告均先l1_submit_report再由用户审核；非成功结案须真实任务证据。新增入口需安装ABI7主包，历史CLI和已开工旧任务保留原收据，不得伪造先审后规划的历史或重开最终报告。详见[完整流程与恢复](guides/flow-recovery.md)。

3.13.0本地门禁补充：[候选测试契约](guides/verification-contract.md)要求实际被测来源和逐项必需结果双重核验；独立test在隔离副本写产物，原输入不可变。额度暂停可重新规划但不扩大上限；初始化一次提交完整委托/需求审查状态，纯参数拒绝不产生UNKNOWN。真实中断及终态保护保持有效。

## 已有批准的交接

当前需求批准和原生授权变更由控制器直接交接给DOT，不能要求模型重复抄成事实或反复审核。返回结果与Markdown使用摘要及证据索引，完整原始记录保留。开工前只读审核已批准而宿主回执失败时，允许经证据、进程及原生确认恢复，保留已有效批准；不等同于产品操作完成证明，不清除API未决，也不自动升级任务。


3.14.0能力与资源规则：L1/L2/L3/L4/L5具备同等完整工具能力，以职责和当前任务限制行为。规划前可用dot_research收集网页、文件和环境证据，DOT可直接请求调查；普通技术查证不计需求修订或实现派工。资源追加由L1评估并自主批准，不再要求用户审批资源上限；目标、验收、操作范围和用户明确截止时间不因此改变。新任务默认采用，旧任务经明确展示此变更的原生升级后采用；保留原始确认和全部累计消耗。详见[能力与资源规则](guides/agent-capabilities.md)。


3.16.0 L2直接工具：DOT可直接读写/编辑文件、列举/创建目录、执行命令、抓取网页和搜索，也可委派调查。工具结果及来源进入research证据与同一API账本；缺资料先自行查证并提出方案，不能仅退回问题。写入限当前授权路径或L2工作材料目录，命令能力不限定版本查询；职责和操作范围仍有效，产品实现交L3、独立验证交L4、需求修订批准交L1。命令执行器不是OS沙箱，不得修改审批、凭据或历史。失败先分析；结果未决保留恢复保护，非成功结案仍须L1评估。详见[能力指南](guides/agent-capabilities.md)。
