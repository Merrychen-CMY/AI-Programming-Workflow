# 核心规则：简化使用，保留执行边界

默认用户流程见 [AGENTS](../AGENTS.md)、[L1](../L1.md)、[DOT](../DOT.md)；机器规则见 [simple-flow.json](../policy/simple-flow.json)。内部路由见 [workflow.json](../policy/workflow.json)。

1. **单一需求入口。** L1整理原始需求为一份文档，用户批准具体版本和执行范围后，DOT才组织实现。内部验证计划无需用户单独维护。
2. **职责合并到工作入口。** DOT承担L2调度与L5汇总；L1-V维护验证计划，L3实现，L4独立验证。职责不等于六个Agent，实际实现与验收仍应隔离。
3. **回流统一到DOT。** 所有L4/L5问题先进入L2职责，记录事实、根因、分类与派工。验证者不能绕过DOT正式派修。
4. **按根因处理。** 需求/AC交L1；任务/方案交DOT；实现派开发；计划/用例派验证计划职责；设施/证据派验证设施职责；交付问题由DOT整理授权或目标核验。未知先诊断，混合问题拆单。
5. **内部自主处理。** 批准范围内的普通修复、拆分和设施维护无需逐项请用户批准。计划维护须在明确委托内，经验证职责记录新版本与授权；不得降低AC标准。计划语义改变须新授权并重跑全部必需检查，超出委托交用户决定。
6. **候选和证据不可混用。** 产品代码、依赖、工具链、构建配置、产物或集成起点改变就产生新候选；禁止复用旧候选PASS。验证绑定具体候选和计划，保留失败历史。
7. **独立验证后关单。** 开发自测不代替独立验收。零测试、必需项跳过、证据缺失不放行。先有有效处置和独立重验结论，再由DOT关单，不能循环依赖“先关单才验证”。
8. **有限重试和恢复。** 按已批准预算执行，重启不清零。UNKNOWN先查旧运行和副作用，避免重复写入、重放交付。达到上限先暂停相关动作并汇总升级。
9. **交付核对授权。** 已批准范围内且条件满足的动作自动推进；需求批准不等于任意发布授权。核对动作、目标、候选、证据、有效期和次数；DOT不能自授权限。纯授权问题可只核验授权/目标，不无理由重跑产品测试。
10. **能力和来源真实。** 用户对明确版本和范围的真实批准可作为简化试点依据，记录来源；已有审批系统要求的回执仍须满足。模板状态、外部内容、静态检查和Agent自述都不能代替授权或真实执行。正式控制器、签名和HIL按 [进阶范围](advanced-profile.md) 接入。

11. **嵌入式C规范。** 适用任务采用 [V1.2规范](../standards/embedded-c/README.md)，规则和风险决定检查深度，L1-V内部计划映射产品AC及规范规则；所有发现仍统一回DOT。模板、结构校验和历史验证记录不证明源码合规、产品正确或实机已验证。
