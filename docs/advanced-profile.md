# 本地与正式集成的适用范围

当前用户主线是需求审核、DOT执行计划审核、最终报告审核。内部L1-V和L2～L5职责保留；用户不逐项维护内部对象。原21章保留正式控制器、签名审批、govrail、CI、HIL和交付守卫的技术条件，不能用旧章节跳过当前三次用户审核。

| 事项 | 本地运行器 | 正式接入 |
| --- | --- | --- |
| 用户审核 | 用户在终端确认需求、计划、报告的摘要 | 由受保护审批渠道记录同样的明确对象 |
| 身份与权限 | 同一用户账户下的独立Codex会话；有记录但无账户安全隔离 | 实际执行身份、工作区、密钥、门禁隔离 |
| 运行与恢复 | 本地状态、累计预算、候选和证据 | 持久化控制器、幂等锁、可信事件及恢复服务 |
| 验收 | 实际配置的独立测试及审核，报告待用户审批 | 受保护CI/govrail和可信证据服务 |
| 交付 | 止于DELIVERY_READY；不执行外部交付 | 守卫核验已批准报告、精确动作/目标与授权，记录真实回执 |

本地终端审批不是身份认证或防篡改审批服务，摘要不是数字签名。Agent不能代用户输入确认。已有正式门禁照常生效，不能换成本地模式绕过。

## 职责与升级

L1负责产品需求/AC，用户实际批准。DOT承担L2拆解、依赖、根因与派工、L5报告/风险/交付申请；L1-V负责验证计划。开发、测试和审核分别独立执行，内部角色组合不削弱独立性。

计划内普通修复及等义检查维护无需逐项用户批准；改变需求/AC先重审需求，改变已批准执行计划的实质范围、方案、必需检查、权限或预算重审计划。纯候选重绑不能被扩大成修改检查语义的授权。

## 原技术章节的解释

G1开工必须同时满足需求审核和执行计划审核。G3的独立证据是成功报告的前提；G4必须在最终成功报告经用户审核后校验具体交付授权。失败报告审核不构成G3 PASS，也不授权继续重试。若有有限交付预授权，仍不能跳过用户报告审核。

相同范围的规则冲突时停止受影响动作并报告，不自行选择宽松规则。48项真实系统/HIL拒绝测试仍为NOT_RUN；本地单元测试不证明这些服务已经接入。
