# ReqPilot 3.13.3

修复真实开工前需求审核已批准、但宿主回执中断且DOT反复要求批准资料的问题。

- 所有审核、批准及暂存回执副本都压缩历史，保留原始JSON和证据。宿主区分输出超限、取消和等待超时。
- DOT直接收到当前有效需求批准、原生批准的额度变更、当前上限/分配和累计用量。不再要求L1把系统已有批准抄成新事实；真实新事实仍需独立复核。
- 审核Markdown保留结论、问题、批准、用量及证据索引，不重复嵌入原始命令日志。
- 只对开工前已完成且证据完整、批准有效的审核增加受控恢复。核验原进程及后代，Windows PID复用须由OS创建时间证明；仍须原生核实与批准，保留原批准、历史和消耗。
- 维护运行包可以核对旧任务，但不切换任务固定版本。恢复后旧任务仍须独立原生升级，并复核受影响基线；未决API与产品执行中断不因此清除。

安装`reqpilot-3.13.3.tgz`并让Harness重新加载插件。保持ABI8；新恢复路由涉及宿主启动层，仅下载运行包不足以应用。保留原会话，先由L1提交真实恢复方案并展示原生确认，再预检和批准任务升级。详见[恢复步骤](../guides/flow-recovery.md)。

本地验证：Python 720通过、3项平台跳过；插件154通过、1项平台跳过。覆盖真实JS/Python管道、控制器及隔离测试进程；模型和原生确认使用夹具。真实已发布3.13.0包的迁移保留原授权、消耗和已完成实现。真实故障记录只读复核，未修改原任务或调用付费模型；不作为用户产品/HIL验收。
