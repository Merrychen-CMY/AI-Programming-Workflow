# ReqPilot 3.13.0

修复完整工作流审核中的七项缺口，并补齐L2方案交接、本地设施恢复和使用指南。

- 当前候选必须提供受控测试契约：真实源码/构建/被测产物来源、精确必需用例和有理由的不适用项。旧build、必需skip/缺项、框架整体失败及被改写的结果不能进入成功报告。
- 独立test拥有专用可写产物目录，源副本保持只读并核验摘要；代码审核和诊断继续只读。
- 实现额度不足先交L1，可在原上限内重新拆分或合并未完成派工；仍保留全部AC和独立验证，已初始化任务修订并重审计划。
- 初始化在委托和原需求审核承接完整后一次提交状态；当前版本、旧版半状态及原子写入失败的临时文件可经专用核验恢复。完整状态及真实执行中断不重置。
- 空参数在派工前正常拒绝，不制造UNKNOWN；真实中断保护保留。
- L3获得L2完整修复方案、原失败、验证步骤、资源与权限边界。L4只执行计划中已批准的本地设施动作；缺方案或权限交L1，恢复失败回L2。
- 新增3.12.1迁移来源。旧计划缺测试契约时进入待修订，纯拒绝不启动审核；修订、独立重审后继续未完成工作。

保持ABI8。安装`reqpilot-3.13.0.tgz`；已开工任务仍固定旧运行版本，需在原会话预检并通过原生升级确认。升级不重置授权、消耗或历史，不撤销最终报告。

当前自动来源核验支持Python unittest/pytest与直接CMake/CTest；通用脚本、专用硬件验证和外部交付不能仅凭一条PASS声明接入。缺少适配能力时由L1协调，并保留任务问题。真实模型、实际Harness聊天及用户产品/HIL尚未作为本次端到端验收对象。详见[候选测试契约与设施恢复](../guides/verification-contract.md)。
