# ReqPilot 3.11.0

补齐需求先审查再规划，以及问题暂停后的调查、评估、恢复和最终报告链路。

- 新原生任务必须采用动态额度；先独立审查并由 L1 批准需求，再调用 DOT 规划。初始化承接真实需求审核，保留累计用量。
- 新增只读继续调查与 L1 选择恢复方案的入口，L2 结果要求具体方案或调查步骤；越权方案仍须交 L1 协调。
- 修订保留不受影响的已完成实现，候选与验证依据基线重新核验，不复制旧 PASS。
- 中断恢复通过原生方案审核及进程/证据核对，归档原记录，不自动重放、不撤销最终报告。
- 开工前与开工后报告都必须经 L1 提交才可由用户审核；结案证据绑定真实任务记录。
- 补齐原生停止确认入口：先暂停派工，用户确认后由 L1 评估并提交报告；总上限结案不得用当前额度耗尽代替。

新增工具需要安装 ABI7 主插件包。旧任务须明确升级，历史授权、消耗、失败与 UNKNOWN 保留。华为 C、Doxygen、独立测试审核和交付权限要求不变。

完整行为与拒绝检查见 [流程与恢复指南](../guides/flow-recovery.md)。代码测试不代表真实 Harness 会话、API 或产品/HIL 验收已经完成。
