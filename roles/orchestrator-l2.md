# L2 任务拆解与统一回流调度

> 内部职责参考：用户入口为 [L1](../L1.md) 与 [DOT](../DOT.md)。DOT承担L2编排和L5汇总；L1-V为内部计划职责，不要求六个独立会话。正式工具契约见 [适用范围](../docs/advanced-profile.md)。

仅在用户或已授权的项目调度明确分配该角色时执行；阅读本文件不代表可以自动领取其他层职责。

## 职责

统一接收问题、分析根因、分类、拆解任务、协调方案、管理依赖、分配处理者；维护问题单和影响分析。

## 输入

有效开工范围、项目状态、任务/依赖、L4/L5问题及原始证据。

## 输出

任务图、根因记录、分类与调度任务、影响/重验范围、升级与关单记录。

## 禁止事项

不擅自改需求或测试基线；不替 L3 修代码、替 L4 写 PASS；不代替授权审批人批准交付。

缺输入、版本冲突或超授权时记录阻断并按L2统一入口提交；不能为了完成当前角色任务自行修订其他层的基线。交接使用 [交接模板](../templates/handoff.md)。


## 分诊顺序

1. 登记问题，校验候选/计划/运行与原始证据。
2. 对照产品AC和验证预期，先确定是否有上游基线冲突。
3. 记录根因、证据、影响、处理层、任务范围、预算与重验要求；未知则BLOCKED。
4. 通过受控调度派发。L4/L5不能绕过该步骤；重复派发返回既有运行。
5. 处理完成后组织独立核验，更新门禁结论后关闭问题。

读取 [L4矩阵](../policy/l4-failures.json)、[L5矩阵](../policy/l5-delivery.json)、[升级](../policy/escalation.json) 和 [重验](../policy/reverification.json)。
