# 将规范接入一个实际项目

1. **L1标注适用范围。** 在已有需求文档引用嵌入式C规范V1.2，记录新代码/旧代码迁移范围、已有项目限制、产品指标、硬件条件与授权。只追问会影响实现或验收的未知项。
2. **DOT建立项目入口。** 合并 [原项目入口模板](v1.2/source/project-entry-template.txt) 到产品CONTRIBUTING.md，保留已有约束；AGENTS引用同一入口，不覆盖原有文件。固定规范commit、源码分类、工具版本和配置；数据/校准不使用通用占位值。
3. **DOT记录任务与风险。** 从批准需求派生任务，保留工作区已有改动和失败基线。R0文档/可证明机械变化，R1普通行为，R2资源/驱动/并发/状态算法/标定，R3发布或安全敏感；取最高影响。实现重构不能因为声称行为不变而算R0。
4. **内部L1-V确定必需检查。** 映射产品AC和规范规则；quick日常检查，full适用合入回归，hil硬件行为影响，soak长期行为或发布要求。用实际C实现和独立判据，选择与风险相称的集合，不自动要求每次全部跑。
5. **开发与审查同步。** 复杂流程先列阶段、准入和不变行为，按可读性清单实现并审查；触发项写位置、处理/保留理由及证据。配置/设备/测试工具尚未接入时明确记录，不标为已通过。
6. **失败先到DOT。** 实现或注释缺陷派L3；判据或计划问题交L1-V；设施、采集或工具故障派L4；产品指标或授权变化通过L1处理。检查器逻辑改变也要独立审查，不能让开发者绕过DOT关闭检查。
7. **按最终候选验收。** 重跑受影响检查、关联真实证据，汇总规则覆盖和产品AC、已批准例外、未验证项、固件与恢复方法。必需项不足保持INCOMPLETE，授权另行核对。

对于小任务可以使用简短的等价内部记录，不省略影响执行或验收的信息。原附录中的某ESP32旧代码“仅补注释”限制仅在当前项目明确适用时继承；规范接入本身不是全仓整改或工具链升级授权。
