对应 test-plan.template.json。计划必须能够确定“测试什么、如何施加输入、观察什么、凭什么通过”。机器文件与人工表单选择一个作为权威记录。

单个用例

| 字段 | 填写内容 |
| --- | --- |
| 身份 | 用例编号、需求编号、被测模块、平台和配置。 |
| 前置状态 | 传感器、校准、负载、固件、参数、资源和时间基准。 |
| 输入与步骤 | 精确输入、顺序、时间间隔及是否需要人工或夹具。 |
| 观测方式 | 公共接口、仪器、日志字段或图像；标明实际产品实现。 |
| 判据 | 预期值、单位、容差、响应与持续时间；注明独立依据。 |
| 执行条件 | 必需性、适用性、命令参数、超时和允许重试原因。 |
| 结束处理 | 清理、设备恢复和失败现场保留要求。 |
| 证据 | 原始记录位置、实际值、结论、执行时间与各次尝试。 |

重点核对

覆盖正常、异常和恢复；重构按 READ-008 检查路由、短路、临界区和清理；状态机覆盖关键及禁止转换。

期望值是否独立于本次实现；日志里出现成功字符串是否足以证明要求。

计划是否能识别未发现用例、错误配置、设备不符和必需项未执行。

失败重跑是否保留首次证据；物理操作无法自动完成时是否明确进入 BLOCKED。
