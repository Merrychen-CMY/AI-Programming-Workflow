# 2 开发流程与风险分级

规则 GOV-001、TASK-001、AI-001。流程依据已确认需求与项目预授权推进；常规实现细节由执行者处理。只有影响行为或验收的歧义、超出范围的操作和缺失的必要人工条件需要进一步确认。

| 阶段 | 主要产物 | 进入下一阶段的条件 |
| --- | --- | --- |
| 定义任务 | 需求、允许改动、不变行为、风险及验收要求 | 关键判据有依据；未知项及处理方式明确。 |
| 检查基线 | 源码状态、工具链、设备、已有失败记录 | 可区分原有问题与本次变更；必要环境可用。 |
| 实施变更 | 代码、同步注释及适用测试 | 变更在范围内；接口、资源和状态设计明确。 |
| 验证与修复 | 检查结果、原始证据、各次尝试 | 必需检查满足；修复未弱化判据。 |
| 独立复核 | CI 或独立环境复跑、必要审查 | 结果对应最终源码与配置；硬件证据齐全。 |
| 交付归档 | 变动清单、报告、固件及恢复方式 | 满足第 11 节完成条件。 |

风险等级

| 等级 | 典型变化 | 最低验证方向 |
| --- | --- | --- |
| R0 | 注释、文档及可证明不改变代码或预处理语义的机械格式整理 | 差异与文档检查；必要预处理行为核对。 |
| R1 | 普通模块行为或应用功能 | 相关单元、边界、异常及集成回归。 |
| R2 | 驱动、并发、资源、状态算法或标定 | 主机与回放验证；受影响硬件和时序验证。 |
| R3 | 发布、执行器或安全敏感行为 | 适用完整回归、专项验收及发布审查。 |

风险取最高受影响项，可上调；降低等级必须有项目约定依据。控制流、接口、数据结构、资源或算法重构，即使目标行为不变，也按影响归入 R1 或 R2。发布核对适用证据与最终版本的一致性。特定行业要求由项目补充。

控制流程成本

小任务可以只填写简短任务记录。沿用现有构建和测试框架，用统一入口封装。检查深度与风险相称；必需检查没有执行时不得以“低风险”为由宣称完成。
