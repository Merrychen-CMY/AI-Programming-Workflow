# 编码参考替换与项目适配

当前编码参考为用户提供的《C语言编程规范》，标识 **DKBA 2826-2011.5**，发布日期2011-05-09，PDF共61页。仓库规范版本为 **1.3**，不是华为文档的新版本。具体文件SHA-256见 [SOURCE.json](SOURCE.json)。本文页码按PDF页序，与印刷页号一致。

用户要求更换编码参考，以下为实施差异的明确决策。现有L1→审核→DOT流程、风险分级、独立验证、设备授权和最终版本证据继续有效。

| 项目 | 华为文档依据 | 本项目采用方式 |
| --- | --- | --- |
| 缩进 | 规则9.1，p44 | 改为每级4空格，Tab键转空格；替代旧8宽Tab缩进 |
| 行宽 | 规则9.3，p44 | 由项目配置，保留80列默认可读性目标；原文132是说明值，不是强制行宽 |
| 大括号 | 规则9.5，p45 | 项目继续强制控制语句加括号；依据新增用户要求改为Allman，函数/控制块括号独占一行、else/else if另行，并非华为唯一风格 |
| 新增函数长度 | 规则2.1，p15 | 非空非纯注释行不超过50；算法聚合等例外要记录并获准，替代旧60行建议评审线 |
| 嵌套 | 规则2.2，p15 | 新增函数不超过4层；项目仍在超过3层时提前评审。两条规则分别计，不互相抵消 |
| 扇出与参数 | 规则2.6，p18；建议2.4，p20 | 通常扇出小于7，特殊协调职责记录复核；参数建议不超过5；不机械拆分或制造无意义参数对象 |
| 命名 | 原则3.1/3.2、规则3.1～3.6，p21～24 | 统一语义命名，g_全局、s_静态；新代码不用拼音/匈牙利命名。项目默认下划线，平台适配及已有接口保留兼容性 |
| goto | 建议6.3，p35 | 原文是谨慎使用；保留用户既有的“禁止goto”项目要求，不误写为华为禁止 |
| 注释 | 第8章，p39～43 | 保留中文Doxygen；文件头保留原要求的元数据；不虚构作者/工号/版权，字段省略或版本历史改由版本控制提供均须明确授权例外 |
| 参数检查责任 | 规则2.4，p16；原则13.1，p51 | 项目明确由外部/公共入口验证不可信输入，内部函数使用前置契约；这是对原默认调用方检查的明确适配 |
| .c/.h配对 | 规则1.1，p8 | 除程序入口外自有.c须有同名.h及公开接口；无公共接口的私有.c需明确授权例外，取消默认放宽 |
| 内存释放 | 建议6.1，p35 | 以明确所有权和生命周期为准，异步/DMA不能为了函数退出而过早释放 |

华为原则/规则按其强度执行；建议须评估，偏离说明理由。规则例外记录条款、范围、原因、替代证据、确认依据与复核条件，开发者不能自行放行。改用4空格和50行规则不授权全仓格式化、接口改名或越过当前“仅补注释”限制。

## 各主题的采用与验证

下表是项目实施摘要，不是原文全文。仅按实际变化读取适用主题，由DOT安排规则到任务、测试和审查的映射。

| 主题 | 原文位置 | 实施重点 | 对应项目规则 |
| --- | --- | --- | --- |
| 组织与清晰性 | 第0章，p5～6 | 可读、简洁、一致；例外有评审记录，不能开发者择松执行 | GOV-001、READ-001～008 |
| 头文件 | 第1章，p6～12 | 单一职责、自包含、无环依赖、最少必要包含、接口与实现分离、保护符 | HEADER-001、ARCH-001 |
| 函数 | 第2章，p12～21 | 单职责、规模和嵌套、错误返回、重入保护、参数责任和内部static | C-001、API-001、READ-007 |
| 命名 | 第3章，p21～24 | 英文语义、常用缩写、一致命名、g_/s_和平台兼容 | C-001、READ-005 |
| 变量 | 第4章，p25～28 | 单一用途、初始化、最少全局状态、字节序及类型转换 | DATA-001、RES-001 |
| 宏与常量 | 第5章，p28～31 | 括号、成块、避免多次求值与魔数，尽量用函数或const | C-001、READ-004 |
| 质量与内存 | 第6章，p32～36 | 越界、泄漏、释放后使用、差一错误；分支覆盖和资源清理 | RES-001、ERR-001 |
| 效率 | 第7章，p36～39 | 先正确和可维护，再基于测量优化算法/数据访问；注意实时生命周期 | TIME-001、ARCH-001 |
| 注释 | 第8章，p39～43 | 解释意图、同步维护、接口契约、贯穿case说明，避免无效注释 | DOC-001、API-001 |
| 排版 | 第9章，p44～46 | 4空格、一行一语句、块间空行、操作符间距，行宽/括号由项目统一 | C-001 |
| 表达式 | 第10章，p46～49 | 无未规定求值次序依赖，明确优先级和副作用；不要让重构改变短路 | READ-002、READ-004、READ-008 |
| 编译和版本控制 | 第11章，p49～50 | 本地与CI配置一致，严格告警、局部豁免有依据，提交保持可构建 | GOV-001、TEST-003、EVID-001 |
| 可测性 | 第12章，p50～51 | 清晰边界、统一诊断、内部断言与外部错误检查分开、支持故障注入 | ARCH-001、LOG-001、TEST-001 |
| 安全 | 第13章，p51～59 | 输入/长度/字符串终止、整数与格式串、二进制长度、EOF、命令注入 | API-001、RES-001、ERR-001、TEST-002 |
| 单元测试 | 第14章，p59～60 | 测试与实现同步或先行，关注模块可观察行为和独立判据 | TEST-001、TEST-002 |
| 可移植性 | 第15章，p60 | 保留标准/平台名字，隔离硬件OS依赖，不无必要内联汇编 | ARCH-001、C-001 |

原第16章为延伸阅读，不自动启用另一套编码参考。历史V1.2资料仅供追溯；当前Agent必须读取V1.3及本差异表。
