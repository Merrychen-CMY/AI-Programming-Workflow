# 可读的命名与流程注释

这是2026-11-20用户要求的项目细化，权威条目见[adoption.json](adoption.json) revision 5（PC-U09、12～16及PC-M01/PC-M02）。**冲突时华为规范优先**；Doxygen继续使用。只改当前授权范围内的自有源码，SDK与既有接口兼容边界不变。

## 三处说明各管什么

| 位置 | 读者应该看懂什么 | 写法 |
| --- | --- | --- |
| 功能.c文件开头 | 这个文件负责什么、从哪里进、主要调用顺序和失败去向 | 在Doxygen文件头中补简短文字或ASCII流程，使用真实函数名；保留原有真实元数据 |
| 函数定义上方 | 怎么调用、输入输出、返回值、前提和副作用 | 保留完整且精练的Doxygen；声明处契约同步 |
| 函数内部 | 当前步骤、分支原因、状态提交以及失败后怎么办 | 对应代码右侧短注释，同一函数内对齐成一列，嵌套分支也保持该列；不能用函数头代替 |

不要求每一行都有注释。看注释应能顺着关键路径读懂程序；不把赋值、加一等自明操作重复翻译一遍。注释要与实现一起更新。

## 右侧对齐规则

同一函数内，变量、语句、if/else及其他关键分支的普通行后注释使用同一注释起始列；代码嵌套缩进变化时，右侧注释列不跟着移动。用空格补齐，根据本函数代码长度选择列，不强制所有文件使用某个列号。统一普通注释形式，使起始符和正文各自对齐。

过长时先精简文字，把必要的长背景说明移入函数Doxygen。只有确有华为位置要求或无法合理缩短的代码/注释影响可读性，才记录具体依据采用分组对齐或上方例外；“逻辑段总述”本身不再是例外。不要为排版重写表达式、拆函数或改变执行顺序。80列仍为项目默认目标，不是硬上限。

## 口语化的尺度

| 避免 | 改成（前提是实现确实如此） |
| --- | --- |
| 执行相关初始化操作 | 先申请发送通道 |
| 对返回结果进行异常判断 | 申请失败，直接返回错误 |
| 将enabled设置为TRUE | 通道启用成功后，再标记为可用 |
| 保证数据处理的稳定性和完整性 | 整批检查通过后，才更新累加器 |

口语化是同事间的清楚说明，保留必要术语和准确单位。不要添加情绪、故事、比喻，或把“已提交请求”写成“硬件已完成”。失败时资源由调用者释放就说清楚，不写成此处已经释放。

下面只展示用户截图中初始化逻辑的注释方式，不是完整驱动，也不规定产品参数。配置与函数Doxygen仍须保留。内部流程注释统一放右侧，用空格对齐；不再把简短的逻辑段总述放到代码上方。

```c
status = rmt_new_tx_channel(&channel_config, &driver->channel);     /* 先申请发送通道。 */
if (status != ESP_OK)                                               /* 申请失败，返回错误，由调用者清理资源。 */
{
    log_failure("rmt_new_tx_channel", status, __func__, __LINE__);
    return status;
}

status = rmt_new_copy_encoder(&encoder_config, &driver->encoder);   /* 再创建编码器，供后续发送使用。 */
if (status != ESP_OK)                                               /* 保留失败原因，让调用者清理已有资源。 */
{
    log_failure("rmt_new_copy_encoder", status, __func__, __LINE__);
    return status;
}

status = rmt_enable(driver->channel);                               /* 最后启用发送通道。 */
if (status != ESP_OK)                                               /* 未启用成功，不标记为可用。 */
{
    log_failure("rmt_enable", status, __func__, __LINE__);
    return status;
}
driver->enabled = TRUE;                                             /* 前面都成功了，后续才可使用通道。 */
return ESP_OK;
```

只借鉴用户第二张截图的说明方式，不照搬其所有语法；本项目仍要求if调用先保存结果，并保留原有短路与执行顺序。

## 命名与文件流程

函数用“对象＋动作＋必要去向”或项目已有一致顺序，变量写明实际内容。例如 `iap_file_write_to_flash()`、`file_size_bytes`、`is_write_complete`。`IAP_FileCode_Write2Fls()`的优点是看得出写入方向，但不强制所有项目使用这种缩写；新代码优先使用`flash`、`to`等直接的词。已有约定可沿用，并在模块中解释IAP等领域缩写。不得顺手全仓改名或破坏公开ABI。

功能.c在文件头用真实函数名概括流程，例如现有[累加器教学实现](../doxygen/examples/commented_module.c)：调用方先reset，再add；add检查输入和容量、调用batch_sum检查整批、成功才提交，失败保持原状态。回调/中断另列触发源，不能画成一条假同步链。无需新增绘图依赖，也无需穷举所有工具函数。

## 进入现有工作流

- L1把此规范作为适用C项目基线，不要求用户另填注释清单。
- DOT/L2派工时带上机器清单及具体范围；L3实现并同步文件流程、函数文档、内部注释和受影响名称。
- L4及独立审核会话对照实际候选，检查关键成功/失败分支、清理归属、状态提交、回调关系及名称含义，记录位置与证据。Doxygen仅证明部分文档结构，不能证明注释正确。
- 问题交L2分析，再由L2派L3修复；不让L4直接改产品。纯审查不增加未授权测试，纯注释任务不夹带行为修改；修改后按原候选与重新验证规则处理。

## 宏定义位置

**PC-M01：自有.c中不放#define，宏定义放对应.h。** 公共宏放模块公开头文件；内部宏放对应私有头文件（如led_driver_private.h），不经公共头文件暴露。保留宏值、类型后缀、展开语义、条件编译及定义生效顺序，检查包含依赖和受影响编译单元；不为迁移宏改变业务行为或扩大修改范围。华为规范优先。L2纳入派工，L3实施，L4独立核对候选的.c/.h及编译证据，问题先回L2。

例如led_driver.c只包含所需头文件；截图中的引脚、RMT时序及超时等实现内部宏放led_driver_private.h。公开接口需要的宏才放led_driver.h。示意如下，值仅表示搬移方式，产品参数仍来自实际需求：

```c
/* led_driver_private.h */
#ifndef PROJECT_LED_DRIVER_PRIVATE_H
#define PROJECT_LED_DRIVER_PRIVATE_H

/** @brief 板载LED的数据引脚；保留已确认的引脚号。 */
#define LED_GPIO_NUM 27

#endif
```

```c
/* led_driver.c */
#include "led_driver.h"
#include "led_driver_private.h"

/* 此处保留实现，不定义宏。 */
```

宏仍留在.c、把全部内部宏放公共头文件、迁移时改变数值或宏生效顺序，均不能仅因Doxygen或编译通过就判本项合格。华为HW-P-1.1的私有实现隔离通过私有头文件保持，不将私有宏变为公共接口。

## 入口与模块职责

入口文件负责程序入口、初始化调用和顶层流程组织，可保留少量入口辅助函数；具有独立职责的硬件驱动、协议处理和业务算法放对应.c/.h。不能把完整驱动集中在main.c，也不按函数数量或文件行数机械拆分。内部函数保持static，公共头只公开必要接口，状态和内部宏留在模块实现及私有头文件；保留资源所有权、调用顺序、错误处理和行为，不新增空模块、无意义包装或无关抽象。

小型LED工程采用main.c（入口与灯效调度）、led_pattern.c/.h（颜色及参数计算）、led_driver.c/.h（初始化/发送/清理）即可；驱动内部宏放led_driver_private.h。不要求再增加通用驱动框架或日志模块。L2在现有计划记录此分工，L4检查实际调用、所有权和包含关系。

## 声明与定义的Doxygen分工

公开函数在.h声明上方保存完整Doxygen调用契约，@param及@return/@retval只在该契约处维护；.c定义上方保留Doxygen，用@details/@par说明步骤、状态、副作用和失败处理，并用@see指向对应头文件。参数和返回条件可用普通段落准确说明，不重复机器标签，不对同一声明/定义函数使用自引用@copydoc。无头文件声明的内部函数在定义处完整记录真实参数和返回。不能删掉实现说明或关闭告警来换取通过。

已验证写法见../doxygen/examples/commented_module.c与commented_module.h：头文件保存机器参数契约，实现用段落和头文件引用说明具体步骤。私有函数仍在定义处完整写参数标签。
