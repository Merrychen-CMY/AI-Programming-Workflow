<a id="hw-p-6.1"></a>
## HW-P-6.1 · 质量属性有先后

来源：原则 6.1，PDF第32页。项目级别：**MUST**。采纳方式：ADOPTED。

**项目要求：** 先保证正确、清晰、可维护、可靠和可测，再评估效率与可移植性；个人方便不能压过质量约束。

**适用条件：** 设计取舍和审查

**检查与证据：** 记录质量目标及取舍依据，核对需求和验收目标。

**项目差异：** 保留原条款意图与强度；按本清单实施。

映射：GOV-001, ARCH-001。实施责任：L3；独立验证：L4；发现入口：DOT/L2。

<a id="hw-r-6.2"></a>
## HW-R-6.2 · 所有资源有释放责任

来源：规则 6.2，PDF第34页。项目级别：**MUST**。采纳方式：ADAPTED。

**项目要求：** 内存及句柄、定时器、Socket、队列、同步对象等资源必须明确所有者和释放责任，正常、异常及部分初始化退出均完成应有清理。嵌套所有权按子对象到容器的顺序释放；指针数组和队列销毁前逐个核对自有成员的释放或明确转移；重新分配不得覆盖未处置的旧资源引用。涉及宏内退出也核查清理路径。借用、共享或已转移对象按所有权契约处理，不机械逐个free。

**适用条件：** 资源取得和转移

**检查与证据：** 对照所有权表检查每条正常/异常/部分初始化退出、嵌套结构、指针数组和队列成员、重复取得资源及宏内return/break。执行分配失败注入、重复创建销毁和资源计数检查，确认不泄漏、不重复释放、不释放借用或仍在使用的对象。

**项目差异：** 细化原规则列出的资源清理检查点；将从下层向上层释放限定于实际拥有的嵌套资源，借用、共享和异步对象遵循已声明的所有权及生命周期，不将建议措施机械解释为一律free。

映射：RES-001, READ-003。实施责任：L3；独立验证：L4；发现入口：DOT/L2。

<a id="hw-r-6.2.sub-01"></a>
### HW-R-6.2.SUB-01 · MUST

**细化要求：** 正常、异常及部分初始化退出前，逐项清点本路径已取得且应释放的内存、定时器、文件/Socket句柄、队列、同步及其他项目资源；保留或转移须有明确所有者和最终释放点。

**适用条件：** 取得资源后存在失败、提前返回或阶段性退出

**检查与证据：** 按资源取得顺序构造各阶段失败，检查清理集合及最终资源计数。

来源：PDF第34页，explicit_check。原文规则6.2的异常出口清理清单；与项目所有权转移约定并用。 项目细分ID，非原文编号。

<a id="hw-r-6.2.sub-02"></a>
### HW-R-6.2.SUB-02 · MUST

**细化要求：** 销毁拥有下层资源的结构时先完成下层自有资源的释放或合法转移，再销毁持有其引用的上层容器；共享或借用成员不得由非所有者释放。

**适用条件：** 结构拥有嵌套分配对象或多层资源

**检查与证据：** 审查所有权树和析构顺序；用非空嵌套对象及部分构造失败验证没有失去最后释放引用、重复释放或悬空访问。

来源：PDF第34页，explicit_check。原文明确要求删除结构指针时从底层向上层；按真实所有权解释该顺序。 项目细分ID，非原文编号。

<a id="hw-r-6.2.sub-03"></a>
### HW-R-6.2.SUB-03 · MUST

**细化要求：** 释放指针数组容器前逐个检查已初始化元素所指资源的归属；自有资源先释放或明确转移，空元素、借用元素和共享引用分别按契约处理。

**适用条件：** 数组元素是指针且数组或其元素有独立生命周期

**检查与证据：** 测试空数组、部分初始化、多个自有元素及混合借用元素，核查容器和元素各自的清理责任。

来源：PDF第34页，explicit_check。原文要求确认释放指针数组前各元素已被提前处置；不据此释放借用对象或同一资源的多个别名。 项目细分ID，非原文编号。

<a id="hw-r-6.2.sub-04"></a>
### HW-R-6.2.SUB-04 · MUST

**细化要求：** 再次分配或替换对象时，必须持续跟踪旧引用与所有权，不得覆盖尚未处置的唯一引用；按接口契约处理成功和失败路径的新旧对象。允许先分配新对象，成功后切换并释放旧对象，失败时保留旧对象。

**适用条件：** 重复初始化、重新分配、对象替换或多次请求

**检查与证据：** 连续执行成功和失败的重建路径，检查旧对象引用、失败后的状态和最终累计资源量。

来源：PDF第34页，explicit_check。原文要求避免重复分配内存；这里禁止造成资源丢失的重复分配，不禁止有明确生命周期的多个独立对象。 项目细分ID，非原文编号。

<a id="hw-r-6.2.sub-05"></a>
### HW-R-6.2.SUB-05 · MUST

**细化要求：** 审查现有或经批准保留的含return/break宏时展开其真实控制流，保证隐藏退出不会跳过已取得资源的清理；本条不授权新增违反宏控制流规则的宏。

**适用条件：** 适用代码存在宏内部返回或跳出

**检查与证据：** 展开宏并追踪跳出范围、退出路径和清理语句，执行相应异常分支测试。

来源：PDF第34页，explicit_check。原文把含return/break宏列为资源清理风险；同时遵守项目关于宏控制流的更严格约束。 项目细分ID，非原文编号。

<a id="hw-r-6.2.sub-06"></a>
### HW-R-6.2.SUB-06 · MUST

**细化要求：** 销毁、清空或放弃队列时逐个核对成员资源；队列所有的成员先释放或交给明确接收者，借用/共享成员按契约处置，不能只释放队列容器。

**适用条件：** 队列中承载需要回收的对象或指针

**检查与证据：** 检查有成员、部分消费、取消和失败恢复场景；核对成员、容器与已移交对象各自的释放和去向。

来源：PDF第34页，explicit_check。原文要求检查队列每个成员是否释放；按实际所有权保留合法转移，不重复释放已移交成员。 项目细分ID，非原文编号。

## HW-R-6.3 · 不使用失效对象

来源：规则 6.3，PDF第34页。项目级别：**MUST**。采纳方式：ADOPTED。

**项目要求：** 对象释放或生命周期结束后所有别名、异步回调和DMA访问均不得继续使用。

**项目差异：** 保留原条款意图与强度；按本清单实施。

<a id="hw-s-6.1"></a>
## HW-S-6.1 · 函数资源收尾

来源：建议 6.1，PDF第35页。项目级别：**SHOULD**。采纳方式：ADAPTED。

**项目要求：** 函数取得的资源在结束前释放，或明确转移给持续存活的所有者并说明最终释放点。

**适用条件：** 分配、返回对象及异步传递

**检查与证据：** 逐条退出路径检查所有权，验证转移后释放时机。

**项目差异：** 遵循原文所有权转移说明；异步/DMA对象不得为满足函数退出而过早释放。

映射：RES-001, READ-003。实施责任：L3；独立验证：L4；发现入口：DOT/L2。

## HW-S-6.2 · 评估单分支的反面情况

来源：建议 6.2，PDF第35页。项目级别：**SHOULD**。采纳方式：ADAPTED。

**项目要求：** 普通if也要考虑条件不成立的行为；必要时增加else或说明不动作，守卫返回可以保持简洁。

**检查与证据：** 审查反面路径和状态保持，覆盖相反条件测试。

**项目差异：** 不机械增加空else，不把本建议误作所有if强制else。

<a id="hw-s-6.3"></a>
## HW-S-6.3 · 项目禁止goto

来源：建议 6.3，PDF第35页。项目级别：**MUST**。采纳方式：ADAPTED。

**项目要求：** 自有代码不使用goto，包括错误清理；以明确职责、所有权和清理路径处理退出。

**适用条件：** 所有自有C控制流

**检查与证据：** 检索并语义审查goto，验证替代清理路径不泄漏、不改变时序。

**项目差异：** 原文要求谨慎使用；本项目继承用户禁止goto的更严格要求。

映射：C-001, READ-003。实施责任：L3；独立验证：L4；发现入口：DOT/L2。
