## HW-P-1.1 · 接口声明与实现分离

来源：原则 1.1，PDF第7页。项目级别：**MUST**。采纳方式：ADAPTED。

**项目要求：** 公共头文件只放调用方必需的声明和类型；内部函数、私有宏及数据留在实现内，优先用API而非全局变量暴露状态。

**适用条件：** 公共头文件及模块接口

**检查与证据：** 审查导出符号和头文件内容；确认变量定义在.c，必要static inline有明确理由。

**项目差异：** 保留项目经审查的static inline例外，不把头文件写成私有实现容器。

映射：HEADER-001, ARCH-001。实施责任：L3；独立验证：L4；发现入口：DOT/L2。

## HW-R-1.1 · 源文件与公共接口配对

来源：规则 1.1，PDF第8页。项目级别：**MUST**。采纳方式：ADAPTED。

**项目要求：** 除程序入口外，每个自有.c提供同名.h并声明其对外接口；纯定义头文件不必有对应.c，内部函数声明留在.c。没有公共接口的内部.c不能默认豁免，确需保留须取得绑定条款与范围的明确例外批准。

**适用条件：** 新增源文件和公共接口

**检查与证据：** 核对.c/.h配对、公共接口及入口职责；非入口无同名.h时检查有效例外批准和适用版本，只有职责说明不能放行。

**项目差异：** 取消对私有.c无.h的默认放宽；遵循原规则，仅经正式授权可使用明确例外，不为形式配对制造无意义接口。

映射：HEADER-001。实施责任：L3；独立验证：L4；发现入口：DOT/L2。

## HW-S-1.1 · 模块目录与总接口

来源：建议 1.1，PDF第11页。项目级别：**SHOULD**。采纳方式：ADOPTED。

**项目要求：** 建议将同一模块的源文件集中在以模块名命名的目录内，并提供文件基本名与目录名一致的模块对外头文件；该头文件组织稳定的公共接口，不是无差别包含全部私有头文件。内部子功能关系松散的模块可以直接提供子模块或源文件对应的公共头文件，不强求总接口头。

**适用条件：** 由多个文件组成的模块

**检查与证据：** 分别核对目录归属及名称、模块公共头文件名称、公开接口范围；对于关系松散而无总接口头的布局，记录模块关系与使用需求，不能仅因缺少总头判为失败。

**项目差异：** 保留建议强度；补齐目录名和对外头文件名约束，并保留松散模块可不提供总头文件的原文例外。

映射：ARCH-001, HEADER-001。实施责任：L3；独立验证：L4；发现入口：DOT/L2。

**细化要求：** 同一模块的多个源文件应集中在同一目录。

**适用条件：** 由多个源文件组成的模块

**检查与证据：** 核对模块清单与源文件目录映射。

### HW-S-1.1.SUB-02 · SHOULD

**细化要求：** 模块目录名应采用模块名。

**适用条件：** 具有独立目录的模块

**检查与证据：** 比对模块定义中的名称与实际目录名，偏离须说明理由。

来源：PDF第11页，explicit_check。建议1.1明确目录与模块的命名对应。 项目细分ID，非原文编号。

<a id="hw-s-1.1.sub-03"></a>
### HW-S-1.1.SUB-03 · SHOULD

**细化要求：** 模块应提供对外公共头文件，其文件基本名应与模块目录名一致。

**适用条件：** 需要整体公共接口的模块；不适用松散模块例外时

**检查与证据：** 核对公共头文件的存在、文件名与模块目录名；按项目既定大小写规则检查。

来源：PDF第11页，explicit_check。建议1.1明确整体对外头文件及其命名；不要求扩展名也等于目录名。 项目细分ID，非原文编号。

<a id="hw-s-1.1.sub-04"></a>
### HW-S-1.1.SUB-04 · SHOULD

**细化要求：** 模块对外头文件应集中声明对使用者稳定的公共接口，不能简单汇入全部私有头文件。

**适用条件：** 模块提供总接口头文件时

**检查与证据：** 检查公开声明、包含图及私有接口是否泄漏。

来源：PDF第11页，explanation。原说明将总头定位为面向使用者的接口。 项目细分ID，非原文编号。

<a id="hw-s-1.1.sub-05"></a>
### HW-S-1.1.SUB-05 · MUST

**细化要求：** 模块内部子功能关系松散、整体总接口不适用时，允许直接提供各子模块或源文件的公共头文件；不得机械要求增加总头。

**适用条件：** 有独立接口且内部关系松散的模块

**检查与证据：** 记录模块耦合关系与接口使用方式，核实例外条件；不得把合乎该例外的布局判为违反建议。

来源：PDF第11页，exception。原文明确存在无需模块总头的情况；此MUST约束评审对例外的正确处理，不把建议升级。 项目细分ID，非原文编号。
