# 原说明的技术边界与项目适配

按用户PDF实施条款时，同时核对说明与示例；不能把历史示例的全部写法自动升级为项目要求。以下适配已写入对应逐条要求，不是隐藏豁免。

| 对应条款 | 项目处理 |
| --- | --- |
| 建议2.2，p20 | 返回指针的关键是所指对象仍存活及所有权明确；并非只能返回static局部对象，也可指向仍有效的调用方或动态对象。不能返回生命周期已结束的局部对象。 |
| 建议2.6，p21；原则4.3，p26 | 保留内部函数和状态的static边界，不照搬发布时清空STATIC宏的示例；热补丁需要另行受控设计。 |
| 规则1.6，p10；建议5.2说明，p30—31 | const对象也有存储和链接语义；自有头文件不定义有存储的变量，公开对象在.c定义、头文件声明，避免说明示例与头文件规则冲突。 |
| 建议7.4，p39 | inline不承诺必然展开、代码更小或可调试性不变；按实际编译产物与测量决定。 |
| 规则10.1与建议10.3，p46—49 | 区分运算分组、求值定序与浮点配置。括号并不保证函数实参先后；浮点运算按语言、工具链选项及精度要求核对，不沿用说明中的概括。 |
| 规则13.1，p51—52 | 空字符终止与空指针不同。不同限长库函数有不同契约；strncpy可能不终止，符合C11契约的snprintf在有效n大于0时保留终止位置，n为0不写入，仍须判断返回值、失败和截断。以目标库为准。 |
| 原则12.1，p50 | 可测性需要清楚的行为边界，说明中的单一出口不解释为禁止项目已允许的提前返回；每条退出路径都须完成资源清理。 |

语言边界核对依据：[WG14 N1570 C11委员会草案](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf)，6.2.2（链接）、6.2.4（生命周期）、6.5/6.5.2.2（表达式和调用）、6.7.4（inline）、7.21.6.5（snprintf）。这是解释核对资料，不自动要求项目改用C11；实际项目须记录所用语言版本、扩展和库契约。

其他项目差异（例如goto、Doxygen、80列、花括号、头文件配对、参数检查及例外权限）在 [采用说明](../reference-adoption.md) 与 [逐条清单](coverage.md) 中明确保留。存在未解决冲突时由DOT/L2协调，需求或验收目标变化经L1，开发者不能自行选择宽松解释。
