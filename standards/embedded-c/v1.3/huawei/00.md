# 0 总体原则与规范治理：逐条项目要求

下列文字为本项目的规范性要求，不是华为原文转载。页码按用户PDF页序；条款强度与项目差异分别列出。

实施和独立验证按具体适用条件进行，未检查项不得记PASS；L4发现问题统一交DOT/L2分析和调度。

<a id="hw-g-0.2-1"></a>
## HW-G-0.2-1 · 可读性优先

来源：治理补充 0.2-1，PDF第5页。项目级别：**MUST**。采纳方式：ADOPTED。

**项目要求：** 设计和实现首先让维护者能理解；只有确认性能瓶颈并取得测量证据后才以复杂性换性能。

**适用条件：** 所有自有C设计和修改

**检查与证据：** 评审业务主线；优化任务附瓶颈测量和前后对比。

**项目差异：** 保留原条款意图与强度；按本清单实施。

映射：GOV-001, READ-001。实施责任：DOT/L2；独立验证：L4；发现入口：DOT/L2。

<a id="hw-g-0.2-2"></a>
## HW-G-0.2-2 · 减少不必要复杂性

来源：治理补充 0.2-2，PDF第5页。项目级别：**MUST**。采纳方式：ADOPTED。

**项目要求：** 保留必要职责，清理失效逻辑和重复实现，避免以少写字符代替清晰表达。

**适用条件：** 设计、实现和重构

**检查与证据：** 检查重复、失效分支与职责；删除前核对所有配置及回调入口。

**项目差异：** 保留原条款意图与强度；按本清单实施。

映射：READ-001, READ-006。实施责任：DOT/L2；独立验证：L4；发现入口：DOT/L2。

<a id="hw-g-0.2-3"></a>
## HW-G-0.2-3 · 一致风格与迁移边界

来源：治理补充 0.2-3，PDF第5页。项目级别：**MUST**。采纳方式：ADAPTED。

**项目要求：** 项目选择一致风格；新自有代码按当前规范，旧代码和第三方适配按批准迁移范围处理。

**适用条件：** 新代码、旧代码修改、平台适配

**检查与证据：** 检查项目风格配置和差异范围，确认没有夹带批量重排或改名。

**项目差异：** 本项目保留4空格默认及原ESP32仅补注释的条件性阶段约束；换规范不授权扩大整改。

映射：C-001, GOV-001。实施责任：DOT/L2；独立验证：L4；发现入口：DOT/L2。

<a id="hw-g-0.3-application"></a>
## HW-G-0.3-application · 适用范围与版本

来源：治理补充 0.3-application，PDF第6页。项目级别：**MUST**。采纳方式：ADAPTED。

**项目要求：** 自有及AI生成后纳入维护的C代码执行当前基线；第三方、工具生成及遗留代码按明确边界和迁移记录管理。

**适用条件：** 每个接入项目及基线变更

**检查与证据：** 核对规范版本、commit、代码归属和迁移清单；AI源码不得归类为工具生成豁免。

**项目差异：** 原文组织内部实施范围转为本项目范围，不继承华为内部审批机构或系统。

映射：GOV-001, C-001。实施责任：DOT/L2；独立验证：L4；发现入口：DOT/L2。

<a id="hw-g-0.3-exceptions"></a>
## HW-G-0.3-exceptions · 例外必须经过授权评审

来源：治理补充 0.3-exceptions，PDF第6页。项目级别：**MUST**。采纳方式：ADAPTED。

**项目要求：** 规则偏离记录条款ID、范围、原因、风险、替代措施、证据、确认者及复核条件；开发者不能自行放行。

**适用条件：** 任何原则或规则偏离

**检查与证据：** L4将问题交DOT/L2分类；核查既有授权，需求或AC变化经L1提交用户确认。

**项目差异：** 评审由项目认可的渠道承担；DOT只能在已有权限内调度，不能自行降低标准或批准交付。

映射：GOV-001, EVID-001。实施责任：DOT/L2；独立验证：L4；发现入口：DOT/L2。
