# 9 排版：逐条项目要求

下列文字为本项目的规范性要求，不是华为原文转载。页码按用户PDF页序；条款强度与项目差异分别列出。

<a id="hw-r-9.1"></a>
## HW-R-9.1 · 四空格缩进

来源：规则 9.1，PDF第44页。项目级别：**MUST**。采纳方式：ADAPTED。

**项目要求：** 每级缩进使用4个空格，编辑器将Tab键转换为空格；编辑器/IDE支持显示Tab字符时应启用显示以发现误输入。宏定义、编译开关和条件预处理可顶格或采用统一项目方案。AI编写源码不属于IDE生成代码豁免，明确工具生成且不手工维护的文件按项目生成策略处理。

**适用条件：** 新自有代码及授权格式迁移

**检查与证据：** 核对每级缩进和Tab字符，检查编辑器Tab转空格配置；支持Tab显示时检查已启用或有偏离说明。分别审查预处理布局一致性与工具生成文件范围，不将顶格预处理或批准生成文件误判。

**项目差异：** 保留4空格规则，补入原说明的条件性Tab可视化建议及预处理布局选择；原文IDE向导代码可不改，本项目仅对明确工具生成且不手工维护文件按生成策略处理。

映射：C-001。实施责任：L3；独立验证：L4；发现入口：DOT/L2。

<a id="hw-r-9.1.sub-01"></a>
### HW-R-9.1.SUB-01 · MUST

**细化要求：** 自有或需人工维护的适用代码每级缩进使用4个空格；可配置编辑器时将Tab键设置为插入空格，实际源码不以Tab字符作层级缩进。

**适用条件：** 新增自有代码或已授权格式迁移

**检查与证据：** 检查固定格式配置、编辑器Tab转换设置和实际缩进字符，区分格式迁移范围。

来源：PDF第44页，explicit_check。原文规则9.1的每级4空格及说明中需要打开Tab转空格配置。 项目细分ID，非原文编号。

<a id="hw-r-9.1.sub-02"></a>
### HW-R-9.1.SUB-02 · SHOULD

**细化要求：** 所用编辑器或IDE提供Tab字符可视化功能时，应启用该功能，便于及时发现误输入；无此能力时注明不适用，不假定所有工具都支持。

**适用条件：** 实际使用的编辑器/IDE支持显示Tab字符

**检查与证据：** 记录工具及支持情况，支持时核对显示设置；若未采用记录具体理由，仍须核验源码缩进。

来源：PDF第44页，explanation。原说明将显示Tab表述为支持时应该打开，保留条件性建议强度。 项目细分ID，非原文编号。

<a id="hw-r-9.1.sub-03"></a>
### HW-R-9.1.SUB-03 · MUST

**细化要求：** 不得仅因宏定义、编译开关或条件预处理顶格而判违反程序块缩进；采用自定义预处理排版时同一产品/模块保持一致。

**适用条件：** 预处理指令及宏的布局

**检查与证据：** 对照项目格式约定检查同类指令一致性，不对预处理机械套用代码块层级。

来源：PDF第44页，exception。原文允许预处理顶格或自定义方案，并要求产品/模块一致。 项目细分ID，非原文编号。

<a id="hw-r-9.1.sub-04"></a>
### HW-R-9.1.SUB-04 · MUST

**细化要求：** 识别并记录IDE/工具生成文件边界，明确生成且不手工维护的文件按批准的生成策略处理；不能以AI生成名义将普通自有源码排除出格式要求。

**适用条件：** 工具生成代码或拟豁免格式迁移的文件

**检查与证据：** 核对生成入口、生成标记、维护方式及项目适用性记录。

来源：PDF第44页，exception。原文允许IDE向导生成代码不改；本项目沿用已有较严格生成文件边界，不新增通用豁免。 项目细分ID，非原文编号。

## HW-R-9.2 · 逻辑段之间留空行

**项目要求：** 独立逻辑块及变量说明之后以空行分隔，避免相关段落挤成一片。

**适用条件：** 代码排版变化

**检查与证据：** 检查逻辑块和声明后分隔，结合格式配置审查。

**项目差异：** 保留原条款意图与强度；按本清单实施。

<a id="hw-r-9.3"></a>
## HW-R-9.3 · 项目确定行宽和换行

来源：规则 9.3，PDF第44页。项目级别：**MUST**。采纳方式：ADAPTED。

**项目要求：** 默认80列可读性目标，可记录其他目标；长语句在低优先级操作处分行，续行缩进，操作符随新行且保持语义完整。

**适用条件：** 长表达式和格式配置

**检查与证据：** 检查项目行宽、续行格式与长行原因，不按字符数机械截断。

**项目差异：** 原文132为说明值，不是强制上限；项目80列也不是机械硬限。

映射：C-001, READ-002。实施责任：L3；独立验证：L4；发现入口：DOT/L2。

## HW-R-9.4 · 一行一个语句

来源：规则 9.4，PDF第45页。项目级别：**MUST**。采纳方式：ADOPTED。

**项目要求：** 独立执行或赋值语句分别占行，避免在同一行堆叠多个短语句。

**适用条件：** 语句排版

**检查与证据：** 检查独立语句布局，for头中的语法分隔不误算多条独立语句。

**项目差异：** 保留原条款意图与强度；按本清单实施。

映射：C-001。实施责任：L3；独立验证：L4；发现入口：DOT/L2。

<a id="hw-r-9.5"></a>
## HW-R-9.5 · 控制语句清晰成块

来源：规则 9.5，PDF第45页。项目级别：**MUST**。采纳方式：ADAPTED。

**项目要求：** 控制语句和case/default标签单独组织，执行体缩进；项目要求控制体加花括号，函数左括号另行，短控制语句默认同行。

**适用条件：** 条件、循环、switch

**检查与证据：** 检查分支及括号配置、长条件布局，防止视觉缩进与执行范围不一致。

**项目差异：** 花括号必加是项目更严格要求；原文允许不同括号位置，不声称华为仅允许本默认。

映射：C-001。实施责任：L3；独立验证：L4；发现入口：DOT/L2。

<a id="hw-r-9.6"></a>
## HW-R-9.6 · 运算符间距统一

来源：规则 9.6，PDF第45页。项目级别：**MUST**。采纳方式：ADOPTED。

**项目要求：** 按操作符语义设置间距：同一行的逗号/分号分隔处只在后方留空格；比较、赋值、算术、逻辑及位运算等双目操作符两侧留空格；符号形式单目操作符紧贴其操作数；sizeof等关键字/类型运算按语法分隔，不能合并词元，成员访问的->和.两侧不留空格；if/for/while/switch等控制关键字与后续条件括号间留空格。括号内侧和相邻多重括号通常不额外填空格，操作符分隔不连续留多个空格。长表达式可按原说明为整体清晰适当收紧局部间距，不把缩进、合法对齐或行尾机械算作操作符分隔。

**适用条件：** 表达式排版

**检查与证据：** 使用按语法区分单双目、声明和表达式的格式检查，核对逗号/分号、成员访问、控制关键字和括号间距。对换行、空for分句、行尾、合法缩进/对齐及长表达式例外单独审查，避免字符替换误伤。

**项目差异：** 补齐原规则说明中的具体间距约定和保持长语句整体清晰的局部调整条件；这些是格式要求的操作细则，不将示例值或行尾空白当作强制要求，也不把单目操作符的紧贴关系套用到相邻双目运算符。

映射：C-001。实施责任：L3；独立验证：L4；发现入口：DOT/L2。

<a id="hw-r-9.6.sub-01"></a>
### HW-R-9.6.SUB-01 · MUST

**细化要求：** 逗号或分号作为同一行项目/语句分隔符时，不在其前方加分隔空格，在后续项目之前留一个空格；行尾不补尾随空格，换行、紧邻闭合符号或空for分句按语法布局处理。

**适用条件：** 声明列表、实参列表及for头等使用逗号或分号分隔的代码

**检查与证据：** 按语法位置检查分隔前后间距，涵盖多行列表、末尾分号和for头；不使用无条件字符串替换。

来源：PDF第45页，explicit_check。原文规则9.6的细项(1)指定逗号/分号只后方留空格；示例不意味着在行尾追加空白。 项目细分ID，非原文编号。

<a id="hw-r-9.6.sub-02"></a>
### HW-R-9.6.SUB-02 · MUST

**细化要求：** 比较、赋值及复合赋值、算术、逻辑和位运算等双目操作符一般在两侧各留一个空格，语义和局部调整遵守本条长表达式例外。

**适用条件：** 双目表达式及赋值

**检查与证据：** 区分&、*等符号的单目/双目角色，核对两侧分隔及表达式整体可读性。

来源：PDF第45页，explicit_check。原文细项(2)列出的双目运算间距要求；按操作符语义解释，避免沿用原说明个别类别名称不精确的表述。 项目细分ID，非原文编号。

<a id="hw-r-9.6.sub-03"></a>
### HW-R-9.6.SUB-03 · MUST

**细化要求：** 符号形式的前置单目操作符与其操作数之间不插入空格，后置自增/自减紧贴操作数；取地址、解引用、逻辑非和按位取反等按单目语义处理。sizeof等关键字/类型运算遵守语法分隔，不能合并词元；相邻双目运算符仍按其规则留空格。

**适用条件：** 单目表达式和前/后置自增自减

**检查与证据：** 用表达式语法检查操作符与操作数结合处，不把指针声明或相邻赋值号误判为单目间距。

来源：PDF第45页，explicit_check。原文细项(3)通过单目运算及示例说明紧贴操作数；不是禁止其外侧与其他语法单元正常分隔。 项目细分ID，非原文编号。

<a id="hw-r-9.6.sub-04"></a>
### HW-R-9.6.SUB-04 · MUST

**细化要求：** 成员访问操作符->和.与两侧操作数之间不留空格。

**适用条件：** 结构/联合成员访问

**检查与证据：** 检查成员访问表达式，排除字符串、注释及其他用途的点号。

来源：PDF第45页，explicit_check。原文细项(4)要求成员访问紧密书写。 项目细分ID，非原文编号。

<a id="hw-r-9.6.sub-05"></a>
### HW-R-9.6.SUB-05 · MUST

**细化要求：** if、for、while、switch等控制关键字与紧随的条件或控制括号之间留一个空格，使其与普通函数调用可区分。

**适用条件：** 具有后续括号的控制语句

**检查与证据：** 检查控制关键字到左括号的分隔，避免套用到函数名、宏名或其他括号用途。

来源：PDF第46页，explicit_check。原文规则9.6细项(5)位于下一页，不能因跨页遗漏。 项目细分ID，非原文编号。

<a id="hw-r-9.6.sub-06"></a>
### HW-R-9.6.SUB-06 · SHOULD

**细化要求：** 已经清楚的括号内侧及相邻多重括号之间不额外填充空格，保持表达式自然紧凑；不得为所谓宽松排版机械插入空白。

**适用条件：** 圆括号包围的表达式及多重括号

**检查与证据：** 审查左右括号内侧与连续括号布局，结合长表达式整体清晰度判断。

来源：PDF第45页，explanation。原说明用不需要、不必描述这些位置，保留其避免多余填充的建议含义，不把语法必需分隔误去除。 项目细分ID，非原文编号。

<a id="hw-r-9.6.sub-07"></a>
### HW-R-9.6.SUB-07 · MUST

**细化要求：** 作为操作符分隔使用的空白不连续堆叠两个或更多空格；代码块缩进和单独规定的对齐不属于此处的操作符分隔。

**适用条件：** 表达式中给操作符添加的分隔空白

**检查与证据：** 核对运算符周围空格用途，区分缩进、对齐和普通表达式间隔。

来源：PDF第45页，explanation。原说明明确不要连续留两个以上空格；限制对象是给操作符留空格。 项目细分ID，非原文编号。

<a id="hw-r-9.6.sub-08"></a>
### HW-R-9.6.SUB-08 · MUST

**细化要求：** 长语句若逐处加空格反而损害整体清晰度，允许依据项目统一格式收紧局部间距；不得把此条件性例外扩大为任意省略空格，也不得仅因有合理局部收紧而判违规。

**适用条件：** 过长且密集表达式的局部间距调整

**检查与证据：** 记录或审查整体可读性理由，核对同类表达式一致性；必要时优先合理换行而非挤压。

来源：PDF第45页，exception。原说明允许长语句以整体清晰为目标在局部不加空格；保留原文例外边界。 项目细分ID，非原文编号。
