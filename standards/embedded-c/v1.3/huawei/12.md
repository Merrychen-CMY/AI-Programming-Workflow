# 12 可测性：逐条项目要求

[完整清单](coverage.md) · [使用及证据规则](README.md) · [技术说明适配](technical-notes.md)

下列文字为本项目的规范性要求，不是华为原文转载。页码按用户PDF页序；条款强度与项目差异分别列出。

实施和独立验证按具体适用条件进行，未检查项不得记PASS；L4发现问题统一交DOT/L2分析和调度。

<a id="hw-p-12.1"></a>
## HW-P-12.1 · 模块具备清晰测试边界

来源：原则 12.1，PDF第50页。项目级别：**MUST**。采纳方式：ADAPTED。

**项目要求：** 模块低耦合、契约稳定，前置条件、输入和预期输出明确；关键状态和数据可通过受控接口查询及设置，原子功能具有唯一逻辑入口，相关依赖集中管理。出口按项目既定适配保持清晰行为边界，允许守卫返回；测试接口不得形成生产越权通道。

**适用条件：** 模块设计和测试接口

**检查与证据：** 依据契约编写独立判据；检查原子功能入口映射及无旁路入口，核对关键状态/数据的查询和驱动能力、集中依赖和清晰出口边界。

**项目差异：** 补齐原子功能入口唯一要求。保留已明确的出口适配：唯一出口落实为清晰行为边界，不禁止守卫返回；受控测试接口不能暴露生产越权通道。

映射：ARCH-001, TEST-001。实施责任：L3；独立验证：L4；发现入口：DOT/L2。

<a id="hw-p-12.1.sub-01"></a>
### HW-P-12.1.SUB-01 · MUST

**细化要求：** 模块间接口必须清晰、完整和稳定，降低耦合。

**适用条件：** 模块设计与接口变更

**检查与证据：** 审查接口契约、依赖关系及变更兼容性。

来源：PDF第50页，explanation。原则12.1说明中的单元测试前提。 项目细分ID，非原文编号。

<a id="hw-p-12.1.sub-02"></a>
### HW-P-12.1.SUB-02 · MUST

**细化要求：** 模块功能必须具有明确的前置条件、输入和预期结果。

**适用条件：** 具有可观察功能的模块

**检查与证据：** 检查验收判据是否能独立于实现形成测试预期。

来源：PDF第50页，explanation。源说明列明验收条件的组成。 项目细分ID，非原文编号。

<a id="hw-p-12.1.sub-03"></a>
### HW-P-12.1.SUB-03 · MUST

**细化要求：** 模块内部关键状态和关键数据必须能够被查询，并能通过受控设置或受控输入驱动到测试所需状态。

**适用条件：** 对验收与故障注入有影响的关键状态和数据

**检查与证据：** 列出观测/注入接口并验证测试能力与访问控制；不能以公开生产私有状态替代受控测试。

来源：PDF第50页，explanation。保留源要求，沿用项目对测试接口权限边界的适配。 项目细分ID，非原文编号。

<a id="hw-p-12.1.sub-04"></a>
### HW-P-12.1.SUB-04 · MUST

**细化要求：** 每项模块原子功能必须有唯一的逻辑入口，不能通过多个旁路进入同一原子功能的内部过程。

**适用条件：** 模块原子功能

**检查与证据：** 建立原子功能到入口的映射，检查调用关系和旁路路径；不将唯一入口误解为整个模块只能公开一个函数。

来源：PDF第50页，explanation。补齐原文明确列出的入口唯一要求。 项目细分ID，非原文编号。

<a id="hw-p-12.1.sub-05"></a>
### HW-P-12.1.SUB-05 · MUST

**细化要求：** 模块原子功能出口必须保持清晰可审查的行为边界，所有返回路径满足后置条件和资源约束；项目允许守卫返回。

**适用条件：** 原子功能的正常、异常和提前返回路径

**检查与证据：** 审查所有出口的结果、资源与状态，验证守卫返回不会绕过必需处理。

来源：PDF第50页，explanation。原文要求出口唯一；按已公开项目适配执行，不新增或隐藏本次偏离。 项目细分ID，非原文编号。

<a id="hw-p-12.1.sub-06"></a>
### HW-P-12.1.SUB-06 · MUST

**细化要求：** 模块相关依赖必须集中处理，减少全局变量或以清晰封装隔离。

**适用条件：** 模块外部依赖、全局状态与资源

**检查与证据：** 核对依赖清单、封装边界和可替换测试依赖。

来源：PDF第50页，explanation。源说明要求集中依赖，以减少单元测试困难。 项目细分ID，非原文编号。

<a id="hw-r-12.1"></a>
## HW-R-12.1 · 统一调测配置与源码

来源：规则 12.1，PDF第50页。项目级别：**MUST**。采纳方式：ADAPTED。

**项目要求：** 项目或产品组必须统一维护用于集成测试和系统联调的编译调测开关及配套打印接口，并提供详细说明；测试与发布使用同一维护源码，通过受控编译配置区分。默认只使用已统一规定的开关，确需新增时必须先按既定例外及配置变更程序审核，不能由模块自行另设。

**适用条件：** 调试功能、测试版本及发布配置

**检查与证据：** 核对统一开关/打印接口清单、用途和默认值说明、实际定义及调用、源码来源和候选ID；搜查清单外开关及其审批依据，配置变化按影响重新验证。

**项目差异：** 补齐项目级统一开关和一般不得另设新开关的要求；允许有理由且经既定程序批准的例外。保留相同源码不同配置不是同一候选、不能复用不匹配PASS的项目要求。

映射：TEST-003, EVID-001。实施责任：L3；独立验证：L4；发现入口：DOT/L2。

<a id="hw-r-12.1.sub-01"></a>
### HW-R-12.1.SUB-01 · MUST

**细化要求：** 项目或产品组必须有统一的集成测试和系统联调开关及相应打印函数。

**适用条件：** 具有集成测试、系统联调或调测功能的项目

**检查与证据：** 核对统一接口、开关表与实际定义/调用，检查模块是否自行绕开。

来源：PDF第50页，explicit_check。规则12.1主体是项目或产品组统一，而非仅要求各开关各自受控。 项目细分ID，非原文编号。

<a id="hw-r-12.1.sub-02"></a>
### HW-R-12.1.SUB-02 · MUST

**细化要求：** 统一调测开关和打印函数必须有详细使用说明。

**适用条件：** 已定义的调测开关及打印函数

**检查与证据：** 检查用途、取值、默认配置、启停方式和影响说明是否足以复现构建及调测。

来源：PDF第50页，explicit_check。细化可复现检查点，承接原文详细说明要求。 项目细分ID，非原文编号。

<a id="hw-r-12.1.sub-03"></a>
### HW-R-12.1.SUB-03 · MUST

**细化要求：** 开发、测试与发行必须维护同一份源码，以规范统一的编译开关区分测试和发行配置。

**适用条件：** 测试与发行配置并存的项目

**检查与证据：** 核对源码基线及构建输入，禁止为测试另行维护与发行脱节的代码版本。

来源：PDF第50页，explanation。源说明要求统一源码及编译开关；候选身份仍包含配置。 项目细分ID，非原文编号。

<a id="hw-r-12.1.sub-04"></a>
### HW-R-12.1.SUB-04 · MUST

**细化要求：** 默认不得在统一规定之外另设编译调测开关；确需新增必须说明原因并按既定例外与配置变更程序批准后纳入统一管理。

**适用条件：** 拟新增或清单外的编译调测开关

**检查与证据：** 对照开关清单搜索新增定义，核实原因、批准记录和配置验证，不能仅凭开发者说明自动通过。

来源：PDF第50页，exception。原文为一般不允许，保留例外可能；批准程序沿用项目治理，不声称原文规定了审批工具。 项目细分ID，非原文编号。

<a id="hw-r-12.2"></a>
## HW-R-12.2 · 调测日志统一且可定位

来源：规则 12.2，PDF第50页。项目级别：**MUST**。采纳方式：ADAPTED。

**项目要求：** 项目或产品组统一日志分类及级别，并通过受控配置渠道改变输出内容和格式；关键分支须有日志，建议避免在原子函数内直接记录。调试日志须能定位文件或模块、行号、函数及相关被调用函数，并记录相关错误码和错误环境。实时路径采用有界采集及延后输出等方式保留所需信息，同时遵守ISR、开销与敏感信息要求，不得以场景适配默默删去适用字段。

**适用条件：** 日志和诊断功能

**检查与证据：** 验证统一分类/级别、输出内容及格式各自可配置；覆盖关键分支并核对文件/模块、行号、函数、被调函数、错误码和环境字段。对无对应调用或错误的字段记录适用性理由；实质偏离须既定例外批准，另测有界开销、ISR约束及敏感数据处理。

**项目差异：** 将原先笼统的必要字段按场景设计收紧为明确的原文字段与适用性检查，补齐输出格式可配置及关键分支记录；原子函数内避免日志仍为SHOULD。保留实时安全适配，但通过有界记录/延后格式化输出落实，不以实时性默认豁免原文要求。

映射：LOG-001, TIME-001。实施责任：L3；独立验证：L4；发现入口：DOT/L2。

**适用条件：** 日志和诊断功能

**检查与证据：** 核对日志分类/级别表与调用使用的一致性。

**检查与证据：** 执行内容过滤或字段选择配置，验证输出变化及配置可追溯性。

来源：PDF第50页，explanation。原文给出命令行、网管等渠道，未限定只能采用这些产品形态。 项目细分ID，非原文编号。

**检查与证据：** 执行格式配置并核对实际输出与解析兼容性；仅能调级别不等于格式可配置。

**适用条件：** 影响主要决策、错误处置或验收结果的关键分支

**检查与证据：** 列出关键分支并验证可观测日志；不能只检查统一日志API存在。

来源：PDF第50页，explanation。原文明确关键分支记录要求。 项目细分ID，非原文编号。

### HW-R-12.2.SUB-05 · SHOULD

**适用条件：** 原子函数及其调用边界

**检查与证据：** 审查原子函数日志位置、定位价值与开销；保留时说明评估理由。

来源：PDF第50页，explanation。原文对此明确使用建议语气。 项目细分ID，非原文编号。

**检查与证据：** 核对日志与文件/模块映射；采用事件表或延后解码时须能可靠还原。

<a id="hw-r-12.3"></a>
## HW-R-12.3 · 断言表达内部不变量

来源：规则 12.3，PDF第50页。项目级别：**MUST**。采纳方式：ADAPTED。

**项目要求：** 断言记录内部设计假设，失败提供可定位信息；断言表达式不得承载必须执行的业务副作用。

**适用条件：** 内部契约和不变量

**检查与证据：** 检查断言条件及禁用断言构建的行为一致性，测试失败诊断。

**项目差异：** 无副作用是项目补充边界，防止发布配置移除必要操作。

映射：TEST-001, ERR-001。实施责任：L3；独立验证：L4；发现入口：DOT/L2。

<a id="hw-r-12.4"></a>
## HW-R-12.4 · 外部错误用运行时处理

来源：规则 12.4，PDF第50页。项目级别：**MUST**。采纳方式：ADOPTED。

**项目要求：** 非法输入、链路错误、资源不足等可预期运行时失败必须正常检测处理，不能只用断言保护。

**适用条件：** 边界输入及运行时错误

**检查与证据：** 在断言启用和禁用配置测试非法输入与错误恢复。

**项目差异：** 保留原条款意图与强度；按本清单实施。

映射：API-001, ERR-001。实施责任：L3；独立验证：L4；发现入口：DOT/L2。

<a id="hw-s-12.1"></a>
## HW-S-12.1 · 为测试准备故障通道

来源：建议 12.1，PDF第51页。项目级别：**SHOULD**。采纳方式：ADAPTED。

**项目要求：** 设计可控的依赖替身和故障注入入口，能够验证失败、超时、资源耗尽及恢复。

**适用条件：** 测试设施设计

**检查与证据：** 按风险验证故障可触发、可观测、可恢复，硬件操作核对既有授权。

**项目差异：** 测试通道不能默认对生产开放或绕过设备权限。

映射：TEST-001, TEST-002。实施责任：L3；独立验证：L4；发现入口：DOT/L2。
