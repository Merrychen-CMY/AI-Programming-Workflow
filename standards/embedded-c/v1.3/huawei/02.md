# 2 函数：逐条项目要求

[完整清单](coverage.md) · [使用及证据规则](README.md) · [技术说明适配](technical-notes.md)

下列文字为本项目的规范性要求，不是华为原文转载。页码按用户PDF页序；条款强度与项目差异分别列出。

实施和独立验证按具体适用条件进行，未检查项不得记PASS；L4发现问题统一交DOT/L2分析和调度。

<a id="hw-p-2.1"></a>
## HW-P-2.1 · 一个函数一个职责

来源：原则 2.1，PDF第12页。项目级别：**MUST**。采纳方式：ADOPTED。

**项目要求：** 函数聚焦一个可命名的行为层次，协调流程与具体动作边界明确，避免无关工作捆绑。

**适用条件：** 函数设计和重构

**检查与证据：** 以函数契约和业务步骤复述职责，检查失败路径与测试边界。

**项目差异：** 保留原条款意图与强度；按本清单实施。

映射：READ-001, API-001。实施责任：L3；独立验证：L4；发现入口：DOT/L2。

<a id="hw-p-2.2"></a>
## HW-P-2.2 · 消除有害重复

来源：原则 2.2，PDF第13页。项目级别：**MUST**。采纳方式：ADAPTED。

**项目要求：** 相同职责的重复逻辑优先提炼复用；出现两处时评估，超过三处及时安排消除，并追踪CI中的重复趋势。

**适用条件：** 新增重复或重复逻辑变更

**检查与证据：** 使用固定重复检测配置和审查记录；确认抽取保持求值、时序及错误语义。

**项目差异：** 未部署重复检测工具须记录检查缺口，不宣称自动通过；独立职责相似代码不得机械合并。

映射：READ-006, READ-008。实施责任：L3；独立验证：L4；发现入口：DOT/L2。

<a id="hw-r-2.1"></a>
## HW-R-2.1 · 新增函数规模

来源：规则 2.1，PDF第15页。项目级别：**MUST**。采纳方式：ADAPTED。

**项目要求：** 新增函数NBNC行数不超过50；完整算法等例外须记录并获准。修改旧函数尽量不增加规模。

**适用条件：** 新增函数及受影响旧函数

**检查与证据：** 固定非空非纯注释物理行计数口径，列出超限位置、例外及行为验证。

**项目差异：** 旧代码按迁移范围；普通保留理由不能替代规则例外批准。

映射：C-001, READ-007。实施责任：L3；独立验证：L4；发现入口：DOT/L2。

<a id="hw-r-2.2"></a>
## HW-R-2.2 · 新增函数控制嵌套

来源：规则 2.2，PDF第15页。项目级别：**MUST**。采纳方式：ADAPTED。

**项目要求：** 新增函数控制块嵌套不超过4层；旧函数修改尽量不加深。超过项目3层评审线先审查，不等同于超过4层规则。

**适用条件：** 新增函数及控制流变更

**检查与证据：** 按项目计数口径检查最深路径，例外经授权复核，不能用无意义包装隐藏深度。

**项目差异：** 项目明确函数体不计、else if同层、case标签不另计；超过4层仍需正式例外。

映射：C-001, READ-007。实施责任：L3；独立验证：L4；发现入口：DOT/L2。

<a id="hw-r-2.3"></a>
## HW-R-2.3 · 共享数据的可重入保护

来源：规则 2.3，PDF第16页。项目级别：**MUST**。采纳方式：ADAPTED。

**项目要求：** 可并发调用的函数尽量不依赖共享可变数据；必要访问采用与上下文兼容的互斥或同步，覆盖整个读改写过程。

**适用条件：** 任务、ISR或回调并发访问

**检查与证据：** 审查共享状态与锁/中断边界；进行竞态、重入和适用实机时序检查。

**项目差异：** 不能在ISR使用阻塞互斥；不得把volatile或局部关中断当成跨核同步。

映射：RES-001, TIME-001。实施责任：L3；独立验证：L4；发现入口：DOT/L2。

<a id="hw-r-2.4"></a>
## HW-R-2.4 · 明确参数校验责任

来源：规则 2.4，PDF第16页。项目级别：**MUST**。采纳方式：ADAPTED。

**项目要求：** 外部和公共入口负责不可信输入校验，内部函数可依赖已写明的前置契约；不能双方都漏检。

**适用条件：** 接口设计与边界变化

**检查与证据：** 核对每类输入由谁检查及失败处理，测试非法值和内部契约。

**项目差异：** 原文默认调用方检查；项目明确采用入口校验方案并避免无意义重复。

映射：API-001。实施责任：L3；独立验证：L4；发现入口：DOT/L2。

<a id="hw-r-2.5"></a>
## HW-R-2.5 · 完整处理失败反馈

来源：规则 2.5，PDF第17页。项目级别：**MUST**。采纳方式：ADOPTED。

**项目要求：** 标准库、第三方及自有调用的失败返回、状态或错误标记均须及时检查，失败不能继续当正常结果使用。

**适用条件：** 所有可能失败的调用

**检查与证据：** 列举错误通道，注入失败验证清理、传播和恢复；忽略须有审查依据。

**项目差异：** 保留原条款意图与强度；按本清单实施。

映射：ERR-001, API-001。实施责任：L3；独立验证：L4；发现入口：DOT/L2。

<a id="hw-r-2.6"></a>
## HW-R-2.6 · 合理调用依赖

来源：规则 2.6，PDF第18页。项目级别：**MUST**。采纳方式：ADAPTED。

**项目要求：** 一般函数直接扇出小于7，公共能力合理复用；协调函数特殊扇出记录职责和复核依据，不以层层转发凑数。

**适用条件：** 函数调用结构变化

**检查与证据：** 检查调用图、直接扇出和间接调用，复核协调例外、调用层次及栈影响。

**项目差异：** 原文允许调度职责区别处理；不设置机械扇入下限。

映射：C-001, READ-007。实施责任：L3；独立验证：L4；发现入口：DOT/L2。

<a id="hw-r-2.7"></a>
## HW-R-2.7 · 及时移除废弃代码

来源：规则 2.7，PDF第19页。项目级别：**MUST**。采纳方式：ADAPTED。

**项目要求：** 确认无用的函数和变量及时清理；先检查条件编译、回调注册、链接脚本和外部ABI，不凭文本未引用删除。

**适用条件：** 确认废弃或新引入死代码

**检查与证据：** 结合引用、链接和配置分析确认，再执行受影响构建和回归。

**项目差异：** 清理受当前任务范围约束，遗留未授权部分登记后续任务。

映射：READ-006, C-001。实施责任：L3；独立验证：L4；发现入口：DOT/L2。

<a id="hw-s-2.2"></a>
## HW-S-2.2 · 集中处理隐含状态与IO

来源：建议 2.2，PDF第20页。项目级别：**SHOULD**。采纳方式：ADAPTED。

**项目要求：** 尽量将全局状态、静态局部状态和IO集中于明确边界，其他函数通过显式输入输出工作。

**适用条件：** 有隐含状态或副作用的函数

**检查与证据：** 检查多次调用及并发行为、状态复位、返回指针的所有权和存活期。

**项目差异：** 不采用说明中返回指针必须来自static局部对象的泛化说法；可以指向仍存活的调用方或动态对象，不能返回失效局部对象。

映射：READ-004, RES-001。实施责任：L3；独立验证：L4；发现入口：DOT/L2。

## HW-S-2.6 · 文件内函数保持内部链接

来源：建议 2.6，PDF第21页。项目级别：**SHOULD**。采纳方式：ADAPTED。

**项目差异：** 不采用说明中的发布版清空STATIC宏做法；热补丁须独立接口及授权方案。
