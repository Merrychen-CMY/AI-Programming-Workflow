# 7 日志与异常行为

规则 LOG-001、ERR-001。日志能识别模块、等级、稳定事件标识、事件发生时间及必要上下文；按需附加设备实例、请求号和样本或事务序号。启动记录固件、配置及启动原因，采集工具区分启动段。

| 等级 | 用途 |
| --- | --- |
| ERROR | 操作失败、功能不可用或必须处理的异常。 |
| WARN | 可恢复异常、资源紧张或潜在问题。 |
| INFO | 启动、配置摘要、重要状态变化和必要业务摘要。 |
| DEBUG | 开发诊断、中间状态及详细执行信息。 |
| TRACE | 高频采样、逐事务及详细过程跟踪。 |

等级映射到平台现有机制，TRACE 可合并到详细调试等级。正式配置通常保留 INFO 及以上；DEBUG 和 TRACE 按模块启用。队列类别属于传输策略，不等于日志严重等级。

项目统一调测与日志约定

项目或产品组统一调测编译开关及打印接口，提供用途、取值、默认配置、启停和影响说明；开发、测试及发行维护同一源码，以受控配置区分。默认不得另设开关，确需新增须按既定例外和配置变更程序批准后纳入统一管理；不同配置仍是不同候选基线。

项目统一日志分类和级别，通过命令行、管理接口或等效受控渠道分别配置输出内容及格式。关键分支必须留有定位日志；建议避免在原子函数内直接记录。调试日志须能定位文件或模块、行号、记录函数和相关被调函数，并记录相关错误码、错误环境；无对应调用或错误的字段需适用性理由，实质偏离须获准例外。

输出与过滤

关键任务及中断不阻塞打印。通过有界缓冲，由日志任务或裸机合适上下文输出；中断只使用明确支持 ISR 的接口。定义满队列策略、丢弃计数和异常输出容量。

设备端尽早过滤，减少格式化及入队开销；查看端按模块、事件、等级、时间、实例或序号组合筛选，保留已采集原始记录。关闭的设备日志不能事后恢复。

字段名保持稳定，使用可解析的 key=value、结构化或二进制格式，不强制 MCU 使用 JSON。字段语义变化需版本化。实时路径可用有界事件记录、事件表及延后格式化还原上述定位字段，必须绑定候选源码；不能以实时性为由默认删除适用字段。

高频日志限频、抽样或汇总；重复异常记录首次、次数与恢复。日志参数不承载业务副作用，关闭日志不能改变功能。

异步日志传副本或保持数据生命周期。诊断日志不作为可靠业务记录通道；不输出密码、私钥或令牌。启动及崩溃可采用平台应急输出路径。

异常与恢复矩阵

按模块列出故障的可观察状态、受影响功能、允许继续的功能、资源处置、恢复条件和告警。初始化局部失败能否隔离由系统依赖决定，不能机械忽略错误继续运行。

超时采用总预算，不因重试或部分进展无限延长。异常后保持硬件安全状态。性能测试记录日志配置与输出开销；没有错误日志不能作为功能正确的唯一证据。

安全编码补充（华为第13章）

外部输入作为索引、长度、分配尺寸、循环条件或命令参数前先验证。C字符串必须有有效的\0终止且容量正确，限制长度的库函数也要核对截断和终止语义；二进制缓冲携带显式长度，不能用strlen代替。

整数运算检查溢出、符号转换和截断，格式参数类型与实际实参匹配，不能把外部输入作为格式化字符串。字符I/O保留int返回值，在区分真实字符、文件结束和读取错误前不得收窄。当sizeof(int)==sizeof(char)时，仅保存int或比较EOF不足以区分所有字符；对EOF返回路径必须使用feof()和ferror()核对流状态，并验证目标库行为。不把未经控制的输入拼进shell命令。硬件/OS依赖封装在适配边界，避免重定义保留标识符或无必要内嵌汇编。
